# ESAM-CCLIP-11 优化路线实现说明

## 1. 路线目标

这条路线的目标不是重做一个全新模型，而是在原 `src/hanxue` 的 ESAM 基线上，尽量低风险地把 6 类方案升级到 11 类训练，并且先通过 train/val 对照确认收益，再决定是否做 fullset 收尾提交。

核心思路是：

```text
EfficientSAM 图像编码器
+ ChineseCLIP 文本编码器
+ 自写 FiLM decoder
+ 11 类 prompt prototype
+ text embedding cache
+ 6 类旧 best 权重热启动
+ split 对照训练优先
+ fullset 收尾可选
```

当前默认主线是：

```text
冻结 image encoder
冻结 text encoder
只训练 decoder
默认不使用 image cache
默认先跑 train/val 对照模式
默认从本地 6 类 best 路径热启动
```

当前这套代码建议按下面几条路线使用：

- 路线一：`lite + fullset`
- 路线二：`mid / split + fullset`
- 路线三：`路线二 stage1 + partial unfreeze image encoder`
- 路线三-A：`unfreeze 后 decoder-only recalibrate`
- 路线三-B：`stage2_mild 上做极轻 lastnorm 解冻`
- 路线四：`stage1_rare_rescue`
- 路线五：`新版 sweep + recall 最强两权重平均`
- 路线六：`统一使用新版 inference.py`

其中：

- 路线一是当前最稳主线
- 路线二是当前最标准的桥接线
- 路线三是小范围解冻诊断线
- 路线三-A 是解冻线的校准补救
- 路线三-B 是在 stage2_mild 底座上的极轻赌分分支
- 路线四是路线二的温和 rare 修复线
- 路线五是低风险后处理/权重平均抠分线

## 1.1 当前训练 preset 对照

当前 `src/ESAM-CCLIP-11/config_esam_cclip_11.py` 中可直接使用的 preset 如下：

- `base`
  - 空预设。
  - 适合手工覆盖 `train_json / val_json / epochs / lr`。
- `lite_fullset_polish`
  - 路线一主 preset。
  - fullset，`no_val=True`，偏向稳定收尾。
- `split_bridge_stage1`
  - 路线二第一阶段。
  - split train/val，先做干净续训。
- `split_bridge_stage2_fullset`
  - 路线二第二阶段。
  - 从 stage1 权重继续接 fullset。
- `stage1_rare_rescue`
  - 路线四。
  - 基于 stage1 再做温和 rare 修复。
- `rare_repair_lite`
  - 更偏 rare 修补的 split preset。
  - 强度通常高于 `stage1_rare_rescue`。
- `partial_unfreeze_lastnorm`
  - 路线三默认入口。
  - 小范围打开 image encoder 尾段。
- `partial_unfreeze_last1`
  - 路线三更激进的一档。
  - 尝试打开最后一个 block。
- `unfreeze_recalibrate`
  - 路线三-A。
  - 用于“解冻 1 轮后重新冻结，只训 decoder 做校准”。

因此，不同实验最好直接按 preset 记忆，而不是再按旧目录的 A / lite / mid train 脚本去分。

## 2. 模型结构怎么实现

模型定义在 `common_esam_cclip_11.py` 的 `ESAMCCLIPModel`。

实际由三部分组成：

```text
img_encoder = PureImageEncoder
txt_encoder = FreezeTextEncoder
decoder     = FiLMFusionDecoder
```

来源上：

- `PureImageEncoder` 直接复用 `src/hanxue/models/image_encoder.py`
- `FreezeTextEncoder` 直接复用 `src/hanxue/models/text_encoder.py`
- `FiLMFusionDecoder` 复用 `src/hanxue/models/fusion_decoder.py`

也就是说，这条路线没有改 backbone，也没有加新的 refine head。优化重点放在：

- 类别扩展到 11 类
- 文本提示表达更稳
- 热启动更稳
- 训练流程先做 split 验证，再决定是否 fullset

## 3. 为什么要做 prompt prototype

11 类里有一些类天然更不稳定，比如：

```text
trash can
window
door
fence
pole_light
motorcycle
```

如果每次只用单一 prompt，例如只用 `"trash can"`，文本特征会过于单薄。  
所以 `config_esam_cclip_11.py` 里给每一类配置了多个 prototype，例如：

```text
trash can -> trash can / garbage bin / trashbin / rubbish bin / 垃圾桶
pole_light -> pole_light / street light / lamp / light pole / 路灯 / 灯杆
```

在 `prompt_prototypes.py` 里，流程是：

1. 对每个 alias 分别编码
2. 每个 alias embedding 先归一化
3. 同类 alias 做平均
4. 平均后再归一化
5. 存成该类唯一的 prototype embedding

最后生成 `text_emb_11.pt`，训练时直接按类别读取，不再每个 batch 重跑文本编码。

这个设计的作用是：

- 减少文本侧噪声
- 保持类别表达稳定
- 降低训练时文本编码开销
- 让 11 类扩展比“逐条 prompt 动态编码”更稳

## 4. text cache 怎么工作

text cache 的核心文件是：

```text
test/cache/text_emb_11.pt
test/cache/text_emb_11.json
```

`text_emb_11.pt` 保存：

- 当前 classes
- 每类 prototype embedding
- 每类实际使用的 alias 列表

训练和扫参阶段都会先走 `load_or_build_text_cache()`。

它会做两件事：

1. 如果 cache 已存在且类别一致，直接加载
2. 如果不存在或用户显式传了 `--rebuild_text_cache`，重新构建

同时它会校验：

- cache 的 classes 是否和当前 11 类一致
- 每类 embedding 是否存在
- embedding 维度是否正常

这样可以避免“以前 6 类 cache 被误拿来跑 11 类训练”的问题。

## 5. 数据集怎么构建

数据集逻辑在 `dataset_esam_cclip_11.py`。

输入 JSON 不是标准分割数据集，而是伪标签汇总结果，所以这里做了几层清洗：

1. 过滤 `computer`
2. 过滤不在 11 类内的 prompt
3. 过滤空 mask
4. 训练阶段允许少量负样本
5. 验证/诊断阶段默认不加负样本

为了避免每次都反复解码 RLE，代码会把 mask 落盘成 png cache。

cache key 不是简单的图名，而是：

```text
md5(image_path | prompt | ann_id | rle_hash)
```

这样做是为了避免同一张图、同一类别、不同实例或不同伪标签覆盖。

数据增强上，这条线刻意做得很保守：

- `prompt augmentation` 默认关闭
- `hflip` 只在训练时、且未启用 image cache 时生效

原因很简单：这条路线的目标是稳，不是把增强复杂化。

## 6. 为什么默认冻结 image/text encoder

当前默认配置是：

```text
FREEZE_IMAGE_ENCODER = True
FREEZE_TEXT_ENCODER = True
TRAIN_DECODER_ONLY  = True
```

原因有三点：

1. 训练数据本质上是伪标签，不够干净  
   全量解冻 backbone，容易把伪标签噪声学进 encoder。

2. 时间成本有限  
   只训 decoder，迭代更快，也更适合先做 split 对照，再决定是否补一轮 fullset 收尾。

3. 当前最强先验已经在旧 6 类权重里  
   更合理的做法是保住原先 image/text 对齐能力，把 11 类适配压力放到 decoder。

另外，训练时虽然会调用 `model.train()`，但代码又显式把冻结的 encoder 切回 `eval()`，保证：

- image encoder 始终用稳定推理态前向
- text encoder 始终用稳定推理态前向
- 真正训练的只有 decoder

## 7. 旧 6 类权重怎么热启动

热启动逻辑在 `model_esam_cclip_11.py`。

这里专门做了 flexible checkpoint load，因为旧工程和当前工程的 key 名不一定完全一样。

支持的 remap 包括：

```text
image_encoder. -> img_encoder.
text_encoder.  -> txt_encoder.
fusion_decoder. -> decoder.
```

同时还会去掉常见前缀：

```text
module.
model.
```

加载时会打印：

- matched_keys
- decoder_matched_keys
- missing_keys
- unexpected_keys
- shape_mismatch

并且有一个硬保护：

```text
decoder_matched_keys == 0 时直接报错
```

这是为了防止“看起来 resume 了，实际上 decoder 一点没热启动上”的假成功。

## 8. 全集训练模式怎么实现

训练入口在 `train_esam_cclip_11.py`。

这条线现在支持两种模式：

### 8.1 常规 train/val 模式

- 构建 train_dataset
- 构建 val_dataset
- 每个 epoch 做 validate
- 保存 `best_all11.pt / best_old5.pt / best_rare.pt`

### 8.2 fullset 收尾模式

通过：

```bash
--no_val
--no_train_split_filter
```

实现逻辑是：

- `train_json` 直接使用 `all-nocomputer.json`
- 不使用 `train_list` 做过滤
- 不构建 `val_dataset`
- 不构建 `val_loader`
- 不调用 `validate()`
- 不保存 best 系列 checkpoint
- 每轮仍保存 `last.pt`
- 最终额外保存 `final_fullset.pt`

这样做的目的不是替代 split 主线，而是在 split 已经验证有效之后，再把“全集训练直接提交”作为第二阶段收尾手段。

## 9. loss 和类别平衡怎么处理

训练使用三种损失的组合：

```text
BCE + Dice + Focal
```

对应权重在配置里是：

```text
BCE_WEIGHT   = 1.0
DICE_WEIGHT  = 0.5
FOCAL_WEIGHT = 0.5
```

同时还叠加了类别权重 `CLASS_WEIGHTS`，让稀有类在 loss 上更有存在感。

此外还用了两层样本侧调节：

1. 少量负样本
   - `NEGATIVE_SAMPLE_RATIO = 0.05`
2. 稀有类 oversample
   - `RARE_OVERSAMPLE` 现在只对最稀缺的 `trash can / fence / pole_light / motorcycle` 做温和重复采样

这条线不是靠复杂模型提 rare class，而是靠：

- class weight
- 温和 rare oversample
- prototype 文本表达

三者一起抬 rare，但默认不会像旧版那样强推 rare，避免先把 old5 冲掉。

## 9.1 stage1_rare_rescue 怎么实现

`stage1_rare_rescue` 是当前新增的温和 rare 修复 preset，目标不是把路线二改成 rare-heavy，而是在 `split_bridge_stage1` 已有权重基础上，再做一小段 split 训练，尝试把 rare 往上抬一点，同时尽量保住 old5。

当前实现特点：

- 继续使用 split train/val
- 继续只训练 decoder
- `unfreeze_image_mode = none`
- `rare_balance_enabled = True`
- `old_class_sample_ratio = 0.85`
- `rare_class_keep_ratio = 1.0`
- `negative_sample_ratio = 0.02`
- rare `oversample = 2`
- rare `class_weights` 最高只到 `1.75`

也就是说，这条线不是强 rare-balanced，而是：

```text
轻度压 old
+ 轻度补 rare
+ 保持 split 验证
```

训练输出上，除了原来的：

- `best_all11.pt`
- `best_old5.pt`
- `best_rare.pt`

还会额外保存：

- `best_rescue.pt`

它对应的 `rescue_score` 会同时考虑：

- `all11`
- `rare`
- `old5` 下滑惩罚

所以它更适合拿来筛“rare 涨了但 old5 没明显崩”的候选权重。

## 10. 为什么 image cache 目前默认关闭

代码里保留了 image embedding cache 能力，但默认：

```text
USE_IMAGE_CACHE = False
```

原因不是它不能做，而是当前阶段性价比不高。

问题主要有两个：

1. image cache 只适合 image encoder 完全冻结
2. 一旦缓存了 embedding，随机翻转等增强就必须严格受控

所以现在代码里有保护：

- `use_image_cache=True` 时必须 `freeze_image_encoder=True`
- 启用 image cache 时训练集 `hflip_prob` 会自动变成 0

也就是说，这个能力现在是“保留但不默认启用”，方便后面需要再开。

## 11. 训练后诊断评估是干什么的

`train_esam_cclip_11.py` 里增加了可选参数：

```bash
--train_eval_after
```

它不是验证集评估，也不是榜单分数模拟。  
它只是一个伪标签拟合诊断工具。

训练结束后它会：

1. 重新构造一个不带增强的训练集诊断 dataset
2. 可选随机抽样一部分样本
3. 用 `VAL_THRESHOLDS` 做二值化
4. 统计伪标签拟合指标

输出包括：

- `train_diagnostic_metrics.json`
- `train_diagnostic_per_class.csv`

看这个指标的正确方式是：

```text
它只能告诉你模型有没有明显学崩
不能代表真实榜单表现
```

## 12. 阈值和后处理扫参怎么做

扫参脚本是 `sweep_thresholds_11.py`。

它读取：

- 一个训练完成的 checkpoint
- 一个用于诊断/扫参的伪标签集
- text cache

然后对每个类别扫：

- threshold
- min_area
- fill_holes

当前这版 sweep 已经扩展到多种模式：

- `best`
- `recall`
- `fine_recall`
- `hybrid`
- `hybrid_safe`

其中：

- `best` 偏 old 稳定性
- `hybrid` 是 old 走 `best`、rare 走 `fine_recall`
- `hybrid_safe` 则更保守：
  - old5 固定使用 route2 hybrid 当前最优配置
  - rare 只允许在当前阈值及更高阈值里搜索
  - rare 的 `min_area / topk_components` 固定，不再放大搜索范围

最终输出：

- `best_thresholds.json`
- `best_postprocess.json`
- `threshold_sweep_summary.csv`
- `sweep_summary.json`

如果传了 `--write_back_checkpoint`，还会把：

- `val_thresholds`
- `postprocess_cfg`
- `img_size`

写回 checkpoint。

这个阶段的作用不是训练模型，而是把“每类阈值”和“每类后处理”调得更合理。

## 13. 这条优化路线的优势

这条路线的优势不在于结构炫，而在于它的工程风险低：

1. backbone 不改，复用旧 ESAM 能力
2. 6 类旧权重可以稳热启动
3. 11 类扩展主要靠 prompt prototype 和训练流程调整
4. 全集训练和验证集 best 逻辑已经拆开
5. 提供了 text cache、诊断评估、阈值扫参这三层配套工具

它本质上是一条“以稳定提交为目标”的升级路线，而不是纯追求复杂结构的实验路线。

---

## 14. 当前还存在的边界

这条路线虽然稳，但也有边界：

1. 仍然依赖 `src/hanxue`
   - 当前是复用旧代码，不是完全独立工程

2. 训练信号仍然来自伪标签
   - rare class 上限仍然会受伪标签质量限制

3. 当前默认只训 decoder
   - 收敛稳，但 ceiling 可能不如精细解冻

4. `train_diagnostic` 不是榜单替代
   - 只能看有没有学崩，不能直接拿来判断提交好坏

所以这条路线的定位很明确：

```text
先用 split 模式确认 11 类标签是否真的优于 6 类基线
再决定要不要跑 fullset 收尾拿 final_fullset.pt
最后再考虑是否继续做更激进的结构或训练增强
```

---

## 15. 一句话总结

`ESAM-CCLIP-11` 这条优化路线，本质上是：

```text
在旧 ESAM 6 类基线之上，
用 prompt prototype + text cache + 温和 rare 重加权 + split 优先训练流程，
把模型稳定升级到 11 类，并保留 fullset 收尾能力。
```
