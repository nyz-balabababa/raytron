# ESAM-CCLIP-11 训练运行说明文档

本文档说明 `ESAM + ChineseCLIP + 自写 decoder` 的 11 类训练流程。
当前默认目标是：**先用 train/val 对照模式验证“6 类 best 热启动 + 新 11 类标签”是否真的带来收益，再决定是否追加 fullset 收尾训练。**

------

# 0. 当前五条优化路线

结合当前 `src/ESAM-CCLIP-11` 已经改过的训练、sweep 和推理脚本，现在建议统一按下面几条路线理解：

## 0.1 当前 preset 有哪些

当前训练入口统一是 `src/ESAM-CCLIP-11/train_esam_cclip_11.py`，配置里的可用 preset 为：

- `base`
- `lite_fullset_polish`
- `split_bridge_stage1`
- `split_bridge_stage2_fullset`
- `stage1_rare_rescue`
- `rare_repair_lite`
- `partial_unfreeze_lastnorm`
- `partial_unfreeze_last1`
- `unfreeze_recalibrate`

可以把这些 preset 理解成“当前代码里已经写好的训练模板”。其中：

- `base`：空模板，适合你自己手工传所有参数。
- `lite_fullset_polish`：路线一主模板。
- `split_bridge_stage1` / `split_bridge_stage2_fullset`：路线二两阶段模板。
- `stage1_rare_rescue`：路线二 stage1 上的温和 rare 修复模板。
- `rare_repair_lite`：更偏 rare 修补的实验模板。
- `partial_unfreeze_lastnorm` / `partial_unfreeze_last1`：路线三的 partial unfreeze 模板。
- `unfreeze_recalibrate`：解冻后重新冻结、只训 decoder 的校准模板。

## 路线一：lite + fullset

- 这是当前最稳的主线。
- 对应训练入口：
  - `train_esam_cclip_11.py`
  - preset：`lite_fullset_polish`
- 目标是基于 `lite` 底座继续吃 fullset 覆盖。

## 路线二：mid + 分集训 + fullset

- 对应 `split_bridge_stage1 + split_bridge_stage2_fullset`
- Stage1 先做分集/分级干净续训
- Stage2 再接 fullset
- 目标是把“分集更干净”和“fullset 更全”拼起来

## 路线三：路线二 Stage1 + partial unfreeze image encoder

- 对应：
  - `--unfreeze_image_mode`
  - 推荐 preset：`partial_unfreeze_lastnorm`
- 这条线只做小范围 image encoder 解冻
- text encoder 仍然始终冻结
- 当前更适合作为诊断增强线，不是默认主线

## 路线四：stage1 rare rescue

- 对应 `stage1_rare_rescue`
- 从 `split_bridge_stage1` 的 `best_all11.pt` 继续 split 训练
- 目标是温和提高 rare 类价值，同时尽量守住 old5
- 仍然是：
  - `no_val=False`
  - `no_train_split_filter=False`
- 会额外保存：
  - `best_rescue.pt`

## 路线五：新 sweep + recall 最强两权重平均

- 所有训练路线先跑新版 sweep
- 优先比较 `recall`，最强候选再跑 `fine_recall`
- 最终可以把 sweep recall 表现最好的两个权重做平均
- 平均后再重新跑一遍 sweep，输出最终 `sam3.pt`

## 路线六：更新推理脚本

- 当前新版 `inference.py` 已支持：
  - prompt normalize
  - 更完整 alias
  - `topk_components`
  - `rare_empty_fallback`，默认关闭
- 现在所有路线最终都建议统一用这版推理脚本做提交

# 4. 每个脚本的作用、输入和输出

## 4.1 `config_esam_cclip_11.py`

### 简单介绍

这个脚本是全局配置文件。
里面写了类别、数据路径、权重路径、训练超参数、阈值、类别权重、后处理参数等。
一般不直接运行，只会被其他脚本导入。

### 输入

无直接输入。
里面配置了默认路径，例如：

```text
TRAIN_JSON
VAL_JSON
TOKENIZER_DIR
EFFICIENT_SAM_CKPT
TEXT_CACHE_PATH
IMAGE_CACHE_DIR
OUTPUT_ROOT
```

当前常用 text cache 对应关系：

```text
lite_fullset_polish         -> test/cache/text_emb_11_lite_polish.pt
split_bridge_stage1/2       -> test/cache/text_emb_11_split_bridge.pt
stage1_rare_rescue          -> test/cache/text_emb_11_stage1_rare_rescue.pt
rare_repair_lite            -> test/cache/text_emb_11_rare_repair_lite.pt
默认兜底                    -> test/cache/text_emb_11.pt
```

### 输出

无直接输出。
它给其他脚本提供配置。

### 是否需要运行？

不需要。

------

## 4.2 `common_esam_cclip_11.py`

### 简单介绍

这个脚本是公共工具文件。
它负责导入旧 `src/hanxue` 里的模块，并封装 `ESAMCCLIPModel`、指标计算、后处理、JSON 保存等函数。
一般不直接运行。

### 输入

无直接命令行输入。
它内部会尝试找到：

```text
src/hanxue/
```

并导入旧代码里的：

```text
data.dataset
models.fusion_decoder
models.image_encoder
models.text_encoder
utils.losses
utils.format_utils
```

### 输出

无直接文件输出。
提供这些功能给训练脚本使用：

```text
ESAMCCLIPModel
compute_metrics
apply_postprocess
save_json
resolve_device
DiceLoss
FocalLoss
```

### 是否需要运行？

不需要。

------

## 4.3 `dataset_esam_cclip_11.py`

### 简单介绍

这个脚本负责读取 `all-nocomputer.json` 里的伪标签，构建训练样本。
它会把 RLE mask 转成图片缓存，加快后续训练读取。
一般不直接运行，由 `train_esam_cclip_11.py` 调用。

### 输入

主要输入：

```text
annotation_json：伪标签 JSON，例如 all-nocomputer.json
image_root：图片根目录，一般是项目根目录
split_txt：图片列表，可选
classes：11 类类别列表
img_size：训练输入大小，例如 768
```

全集训练时：

```text
split_txt = None
```

这表示不按 `train_list` 过滤，直接使用 JSON 里的全部样本。

### 输出

返回 PyTorch Dataset。

同时会生成 mask 缓存：

```text
test/train_output/.mask_cache_esam_cclip_11/<json名>/
```

里面是从 RLE 解码出来的 `.png` mask，cache key 已包含 `image_path|prompt|ann_id|rle_hash`。

### 是否需要运行？

不需要单独运行。

------

## 4.4 `model_esam_cclip_11.py`

### 简单介绍

这个脚本负责加载旧 checkpoint，并做 key remap。
因为旧模型和新模型的模块名可能不一样，所以它会把旧 key 映射到新模型 key。
一般不直接运行，由训练脚本调用。

### 输入

主要输入：

```text
model：当前 11 类模型
checkpoint_path：旧 6 类 best.pt
device：cuda 或 cpu
```

### 输出

把旧权重加载到当前模型中。

日志里要重点看：

```text
decoder_matched_keys
matched_keys
missing_keys
unexpected_keys
shape_mismatch
```

### 成功标志

重点看：

```text
decoder_matched_keys > 0
```

如果是 0，说明旧 decoder 没加载上，训练热启动失败。

### 是否需要运行？

不需要单独运行。

------

## 4.5 `prompt_prototypes.py`

### 简单介绍

这个脚本负责构建 11 类 text embedding cache。
每个类别会用多个 prompt prototype，例如英文、中文别名，然后平均成一个类别文本向量。
一般由训练脚本自动调用。

### 输入

主要输入：

```text
ChineseCLIP text encoder
tokenizer
CLASSES
PROMPT_PROTOTYPES
TEXT_CACHE_PATH
```

### 输出

生成 text cache：

```text
test/cache/text_emb_11.pt
test/cache/text_emb_11.json
```

其中：

```text
text_emb_11.pt：训练真正用的文本 embedding
text_emb_11.json：记录每类用了哪些 prompt alias
```

### 什么时候需要重建？

第一次训练必须加：

```bash
--rebuild_text_cache
```

如果你改了类别、prompt prototype，也要重新加：

```bash
--rebuild_text_cache
```

否则可以不加，直接复用缓存。

### 是否需要单独运行？

一般不用单独运行，训练脚本会自动构建或加载。

## 4.6 `train_esam_cclip_11.py`

### 简单介绍

这是最重要的训练入口脚本。
它负责构建模型、加载旧 6 类 best 权重、读取 11 类伪标签、训练 decoder、保存 split 模式和 fullset 模式所需的权重。
当前推荐先直接用默认的 train/val 对照模式，观察 `best_all11.pt / best_old5.pt / best_rare.pt`，只有确认 split 模式收益稳定后，再切到 fullset 收尾。

当前还支持一个温和 rare 修复 preset：

```text
stage1_rare_rescue
```

它的定位是：

- 基于 `split_bridge_stage1` 的 `best_all11.pt`
- 再做 1 到 2 个 epoch split 训练
- 温和抬高 rare 类价值
- 不走强 rare-heavy
- 额外保存 `best_rescue.pt`

### 输入

常用输入：

```text
--train_json：训练 JSON，推荐 all-nocomputer.json
--val_json：验证 JSON，推荐 val-nocomputer.json
--image_root：图片根目录，默认是项目根目录
--resume_best：旧 6 类 best.pt
--train_list：训练图片列表，默认 trainval_list.txt
--val_list：验证图片列表，默认 val_list.txt
--no_train_split_filter：全集训练时不用 train_list 过滤
--no_val：fullset 收尾时不使用验证集
--epochs：训练轮数
--batch_size：batch size
--workers：DataLoader 线程数
--rebuild_text_cache：重建 text cache
--train_eval_after：训练后是否做伪标签诊断评估，可选
--train_eval_max_samples：诊断评估最多抽样多少训练样本，可选
--train_eval_batch_size：训练后诊断评估时的 batch size，可选
--train_eval_seed：训练后诊断评估抽样随机种子，可选
```

### 输出

默认输出目录：

```text
test/train_output/ESAM-CCLIP-11-split-control/
```

主要输出：

```text
ESAM-CCLIP-11-split-control.log  # 训练日志
config_used.json                 # 本次运行参数
last.pt                          # 每个 epoch 后保存的最新权重
best_all11.pt                    # split 模式下按 all11 mIoU 选 best
best_old5.pt                     # split 模式下按 old5 mIoU 选 best
best_rare.pt                     # split 模式下按 rare mIoU 选 best
best_rescue.pt                   # rare rescue 分数选出的额外 best
final_fullset.pt                 # fullset 收尾模式最终权重
results.csv                      # 训练曲线数据
results.png                      # 训练曲线图
```

如果开启：

```bash
--train_eval_after
```

还会输出：

```text
train_diagnostic_metrics.json
train_diagnostic_per_class.csv
```

注意：这个诊断指标只是“模型拟合伪标签的程度”，不是真实榜单分数。

`--no_val` 模式下还要注意：

```text
不会保存 best_all11.pt / best_old5.pt / best_rare.pt
results.csv 只记录训练指标
results.png 只画训练相关曲线
更适合做第二阶段 fullset 收尾，不适合直接作为第一轮对照实验
```

如果跑的是 `stage1_rare_rescue`，还会多一个：

```text
best_rescue.pt
```

它按 `rescue_score` 保存，分数同时考虑：

- `all11`
- `rare`
- `old5` 下滑惩罚

### 是否需要运行？

需要。
这是正式训练必须运行的脚本。

## 4.7 `sweep_thresholds_11.py`

### 简单介绍

这个脚本用于扫每一类的预测阈值和最小面积后处理。
它需要一个 checkpoint 和一个伪标签验证/诊断集。
如果你走全集无验证直接提交，可以先不跑它。

### 输入

主要输入：

```text
--checkpoint：训练得到的 checkpoint，例如 final_fullset.pt
--val_json：用于扫阈值的 JSON
--val_list：用于扫阈值的图片列表
--text_cache_path：text cache 路径
--sweep_mode：best / recall / fine_recall / hybrid / hybrid_safe
--write_back_checkpoint：是否把扫出来的阈值写回 checkpoint
--write_back_path：写回后的 checkpoint 路径
```

### 输出

默认输出：

```text
test/train_output/threshold_sweep_esam_11/
```

里面包括：

```text
best_thresholds.json
best_postprocess.json
threshold_sweep_summary.csv
sweep_summary.json
```

当前常用 sweep 模式建议：

```text
best         -> 默认稳妥模式
hybrid       -> old 走 best，rare 走 fine_recall
hybrid_safe  -> old5 固定，rare 只做更保守阈值搜索
fine_recall  -> rare 冲分模式
```

如果开启写回：

```bash
--write_back_checkpoint
```

会额外保存一个带阈值的 checkpoint，例如：

```text
sam3.pt
```

### 是否需要运行？

可选。
如果今天时间紧，可以先不跑，直接用 `final_fullset.pt` 提交看分。

## 4.8 `inference.py`

### 简单介绍

这是提交推理脚本，用来把训练好的 checkpoint 转成比赛需要的预测结果。
当前训练流程没有重点修改它。
等训练完成后，再单独检查和适配 inference。

### 输入

通常包括：

```text
测试图片目录
测试任务 JSON
训练好的 checkpoint
输出 predictions.json 路径
```

### 输出

比赛提交文件：

```text
predictions.json
```

### 是否现在运行？

现在先不用。
先把 `final_fullset.pt` 训练出来，再处理推理脚本。

```bash
  --batch_size 4 \
  --workers 4 \
  --rebuild_text_cache
```

说明：

```text
--resume_best：从旧 6 类 best 权重热启动
--epochs 5：先给 split 模式足够轮数观察 old5 和 rare 的平衡
--batch_size 4：正式训练 batch size
--workers 4：读取数据线程数
--rebuild_text_cache：重建 11 类文本向量缓存
```

如果 text cache 已经重建过，第二次跑可以去掉：


# 16. 常见错误和解决方法

## 16.1 `ModuleNotFoundError: No module named 'data'`

原因：

```text
没有找到 src/hanxue
```

检查目录：

```text
project_root/src/hanxue/data/
project_root/src/hanxue/models/
project_root/src/hanxue/utils/
```

解决：

```text
确认新脚本放在 src/ESAM-CCLIP-11/
确认旧 hanxue 代码还在 src/hanxue/
```

------

## 16.2 `train_dataset 为空`

原因可能是：

```text
train_json 路径错
image_root 路径错
JSON 里的 image_path 找不到真实图片
类别 prompt 被过滤光了
```

全集训练建议加：

```bash
--no_train_split_filter
```

如果还是空，检查：

```text
all-nocomputer.json 是否存在
JSON 里的 image_path 是否能在 image_root 下找到
```

------

## 16.3 `decoder_matched_keys=0`

原因：

```text
旧 best.pt 和当前模型 key 对不上
```

解决：

```text
确认 --resume_best 指向旧 6 类 ESAM-CCLIP best.pt
不要误传 EfficientSAM 原始权重
不要误传 CLIPSeg 权重
```

------

## 16.4 CUDA 显存不够

解决：

```text
batch_size 从 4 改成 2
还不行就改成 1
保留 AMP，不要在正式训练时加 --no_amp
```

正式训练建议：

```bash
--batch_size 2
```

或者：

```bash
--batch_size 1
```

------

## 16.5 `results.png` 报错

原因可能是绘图函数没有适配 `--no_val`。
现在代码应该已经适配，如果还报错，检查 `plot_results(history, ..., no_val=args.no_val)` 是否正确调用。
