# 当前可尝试路线总结

## 1. 当前 ESAM 优化主线

现在 `src/ESAM-CCLIP-11` 这套代码，建议按下面 5 条权重路线 + 1 条推理路线来理解，不再按旧的 A / A-lite / mid 混着说。

## 1.0 当前可用 preset 一览

目前 `config_esam_cclip_11.py` 里实际可用的训练 preset 有 9 个：

- `base`：不额外套路线预设，主要用于手工传参。
- `lite_fullset_polish`：路线一主 preset，fullset、`no_val=True`，偏稳的 lite 收尾线。
- `split_bridge_stage1`：路线二第一阶段，split train/val 干净续训。
- `split_bridge_stage2_fullset`：路线二第二阶段，接 stage1 权重做 fullset 覆盖。
- `stage1_rare_rescue`：在 stage1 基础上做温和 rare 修复，仍然是 split train/val。
- `rare_repair_lite`：更偏 rare 修补的 split preset，力度比 `stage1_rare_rescue` 更强。
- `partial_unfreeze_lastnorm`：路线三常用 preset，小范围解冻 image encoder 的最后 norm/尾段。
- `partial_unfreeze_last1`：比 `lastnorm` 更激进一点，尝试解冻最后一个 block。
- `unfreeze_recalibrate`：路线三-A，先解冻过 encoder，再重新冻结，只训 decoder 做 1 轮校准。

路线和 preset 的关系大致是：

- 路线一：`lite_fullset_polish`
- 路线二：`split_bridge_stage1` -> `split_bridge_stage2_fullset`
- 路线三：`partial_unfreeze_lastnorm` / `partial_unfreeze_last1`
- 路线三-A：`unfreeze_recalibrate`
- 路线四：`stage1_rare_rescue`
- 路线五：不对应 train preset，主要对应 `sweep_thresholds_11.py` + `average_checkpoints.py`

### 路线一：lite + fullset

目标：

- 以当前最稳的 `lite` 思路为主线继续抠分。
- 训练上保持 decoder 主训，不大改结构。
- 用 `fullset` 吃覆盖面。

对应代码：

- 训练入口：`train_esam_cclip_11.py`
- 典型 preset：`lite_fullset_polish`

核心特点：

- 偏稳
- 适合作为当前默认主线
- 最适合配新版 `fine_recall / recall` sweep

### 路线二：mid + 分集训 + fullset

目标：

- 先利用分集/分级训练拿到更干净的中间权重
- 再接一段 fullset，把分集的干净和全集的覆盖拼起来

对应代码：

- Stage1：`split_bridge_stage1`
- Stage2：`split_bridge_stage2_fullset`

核心特点：

- 这是当前最标准的“桥接线”
- Stage1 负责干净
- Stage2 负责覆盖
- 是否优于路线一，要看真实 val / sweep / 榜单反馈

### 路线三：路线二 Stage1 + unfreeze encoder

目标：

- 在路线二 Stage1 的 best 权重上，做小范围 image encoder 解冻诊断
- 不解冻 text encoder
- 不做全量 backbone 解冻

对应代码：

- `train_esam_cclip_11.py`
- `--unfreeze_image_mode`
- 推荐 preset：`partial_unfreeze_lastnorm`

当前建议：

- 先只跑 `last_norm`
- 先跑 1 个 epoch 看验证集反应
- 这条线不是默认主线，而是“看有没有额外增益”的诊断线
- 如果 `last_norm 1ep` 后 val 指标有涨，不建议立刻继续第 2 轮解冻
- 更推荐先走“解冻后回冻校准”：
  - `stage1_unfreeze_lastnorm_1ep`
  - `-> freeze encoder`
  - `-> decoder-only recalibrate 1 epoch`

### 路线四：Stage1 rare rescue

目标：

- 在路线二 `Stage1` 的 `best_all11.pt` 基础上继续做一小段 split 训练
- 温和提高 rare 类价值
- 观察 rare 能不能涨，同时 old5 不崩

对应代码：

- `train_esam_cclip_11.py`
- 典型 preset：`stage1_rare_rescue`

核心特点：

- 仍然是 split train/val 模式，不会跑成 fullset
- `rare_balance_enabled=True`
- `old_class_sample_ratio=0.85`
- rare `oversample=2`
- rare `class_weights` 温和抬高
- 会额外保存 `best_rescue.pt`

当前建议：

- 这是路线二的补救/修复线，不是替代路线一的默认主线
- 重点看 `all11 / old5 / rare` 三者能否同时守住

### 路线五：新 sweep + 两个最好 recall 权重做平均

目标：

- 不改训练结构，直接利用已有候选权重做后处理增强
- 所有训练路线都先跑新版 sweep
- 从 recall 结果最好的两个候选权重里再做 checkpoint averaging

对应代码：

- `sweep_thresholds_11.py`
- `tools/average_checkpoints.py`

推荐做法：

1. 所有候选权重先跑 `best` 或 `hybrid`
2. 路线二 fullset / rare-rescue 候选可以额外跑 `hybrid_safe`
3. rare 还想继续抠时，再跑 `fine_recall`
4. 选表现最好的两个候选做平均
5. 对平均后的权重再跑一遍 sweep，重新写回 `sam3.pt`

这条线的本质：

- 不改训练逻辑
- 风险低
- 很适合作为“提交前最后一轮抠分”

### 路线六：更新推理脚本

目标：

- 不改 `predictions.json` 语义
- 不改 RLE 格式
- 在官方单权重提交框架下，做低风险推理优化

当前推理脚本已经支持：

- prompt alias normalize
- 更完整的 alias 映射
- `topk_components`
- `rare_empty_fallback`，默认关闭
- 更紧凑的输出写盘
- 更清晰的 debug summary

对应代码：

- `src/ESAM-CCLIP-11/inference.py`

结论：

- 现在所有路线最终都应该尽量统一用这版新 `inference.py`
- 这样对比更干净，变量更少

## 1.1 路线三后续的两个分支

### 路线三-A：unfreeze 后 decoder-only recalibrate

目标：

- 不继续立刻解冻第 2 轮
- 先把已经被扰动过的 image feature 分布重新和 decoder 对齐
- 看 `all11` 能不能在不掉 rare 的情况下再抬一点

实现逻辑：

```text
ESAM-unfreeze-stage1-lastnorm-1ep/best_all11.pt
-> 冻回 image encoder
-> 只训练 decoder 1 epoch
-> 用更小 lr 做 recalibrate
```

建议参数：

- `epochs = 1`
- `decoder_lr = 5e-6 ~ 1e-5`
- `image_lr = 0`
- `negative_sample_ratio = 0.005`
- `negative_sample_weight = 0.05`
- `rare_balance_enabled = False`
- `old_class_sample_ratio = 1.0`
- `rare_class_keep_ratio = 1.0`
- `no_val = False`
- `no_train_split_filter = False`
- `freeze_image_encoder = True`
- `freeze_text_encoder = True`

适用前提：

- `stage1_unfreeze_lastnorm_1ep` 的 val 指标是正向的
- 但 sweep 还没把它吃出来

### 路线三-B：stage2_mild 上做极轻 lastnorm 解冻

目标：

- 在当前 split 体系里最强的 `stage2_mild_rare_rescue_1ep` 底座上
- 再赌一小步 image encoder 微调增益

实现逻辑：

```text
stage2_mild_rare_rescue_1ep
-> partial_unfreeze_lastnorm 1 epoch
-> freeze encoder
-> decoder-only recalibrate 1 epoch
```

建议参数：

- `epochs = 1`
- `decoder_lr = 5e-6 ~ 1e-5`
- `image_lr = 1e-7 ~ 2e-7`
- `negative_sample_ratio = 0.005`
- `negative_sample_weight = 0.05`
- `rare_balance_enabled = False`
- `old_class_sample_ratio = 1.0`
- `rare_class_keep_ratio = 1.0`

当前判断：

- 路线三-A 优先级高于路线三-B
- 路线三-B 是赌分线，不是默认主线

## 2. 每条路线怎么理解

### 路线一适合什么情况

- 你已经有一个比较强的 `lite` 底座
- 你不想冒太大训练风险
- 你更想先靠 fullset + 新 sweep + 新 inference 稳定吃分

### 路线二适合什么情况

- 你怀疑分集训练确实带来了更干净的 rare / hard case 学习
- 但单纯分集权重又不够强
- 所以希望通过 Stage1 + Stage2 折中

### 路线三适合什么情况

- 你已经拿到了一个不错的 Stage1 权重
- 想验证“轻微放开 image encoder”能不能比纯 decoder 再多一点收益
- 但不想直接冒全量 backbone 解冻的风险

### 路线四适合什么情况

- 你已经有一个还不错的 `split_bridge_stage1` 权重
- rare 指标想再抬一点，但你不想直接切到强 rare-heavy
- 想用 1 到 2 个 epoch 做温和 rare rescue，先看 old5 会不会崩

### 路线五适合什么情况

- 你已经有多条候选路线跑完
- 不想再开太多新训练
- 想直接在现有 best 权重上做后处理和 checkpoint averaging 抠分

## 3. 当前优先级建议

当前建议的优先级是：

1. 路线一：`lite + fullset`
2. 路线二：`mid / split -> fullset`
3. 路线四：`stage1_rare_rescue`
4. 路线五：新版 sweep + averaging
5. 路线三-A：`unfreeze -> recalibrate`
6. 路线三-B：`stage2_mild -> 极轻解冻 -> recalibrate`

原因：

- 路线一最稳
- 路线二最值得验证
- 路线四适合作为路线二的温和补救
- 路线五最省风险
- 路线三-A 适合验证“解冻带来的增益能不能通过校准兑现”
- 路线三-B 更像赌分线，不建议先重仓

## 4. 当前推荐执行顺序

推荐按下面顺序跑：

1. 先训路线一和路线二
2. 如果路线二 Stage1 不够强，再补一条 `stage1_rare_rescue`
3. 候选权重先跑 `best / hybrid / hybrid_safe`
4. rare 还想继续抠时，再跑 `fine_recall`
5. 比较路线一、路线二、rare-rescue 三条线的 sweep 结果
6. 选两个最强候选做 checkpoint averaging
7. 对平均后的权重再跑一次新版 sweep
8. 最后统一用新版 `inference.py`

## 5. 现在你应该怎么看日志和结果

### 训练结果

重点看：

- `mIoU_all11`
- `mIoU_old5`
- `mIoU_rare`
- `pos_mIoU`

### sweep 结果

重点看：

- `best_metric`
- `sweep_mode`
- 每类 `best_threshold`
- 每类 `best_min_area`
- 每类 `best_topk_components`
- 每类 `precision / recall / pred_area / gt_area`
- `hybrid_safe` 下 old5 是否基本锁住
- `best_rescue.pt` 是否优于 `best_all11.pt`

### 解冻实验

重点看：

- `text_encoder trainable params = 0`
- `image_encoder trainable params > 0`
- `image_encoder trainable params <= 5M`
- optimizer 里同时有 `decoder` 和 `image` 两组
- 1 epoch 后 val 指标是否立刻掉点

## 6. 最后结论

现在这套 ESAM-CCLIP-11 代码，不再是单一一条训练线，而是：

- 路线一：`lite + fullset`
- 路线二：`mid + 分集训 + fullset`
- 路线三：`路线二 stage1 + partial unfreeze image encoder`
- 路线四：`stage1_rare_rescue`
- 路线五：`新版 sweep + recall 最强两权重平均`
- 路线六：`统一使用新版 inference.py`

如果只看当前最值得投入资源的方向：

- 主线继续押路线一
- 次主线验证路线二
- 路线四作为路线二的补救验证
- 末端抠分重点放在路线五
- 路线三只做小规模诊断，不建议一开始重仓
