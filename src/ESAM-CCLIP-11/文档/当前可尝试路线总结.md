# 当前可尝试路线总结

## 1. 当前 ESAM 优化主线

现在 `src/ESAM-CCLIP-11` 这套代码，建议按下面 4 条权重路线 + 1 条推理路线来理解，不再按旧的 A / A-lite / mid 混着说。

### 路线一：lite + fullset

目标：

- 以当前最稳的 `lite` 思路为主线继续抠分。
- 训练上保持 decoder 主训，不大改结构。
- 用 `fullset` 吃覆盖面。

对应代码：

- 训练入口：`train_esam_cclip_11.py`
- 典型 preset：`lite_fullset_polish`

核心特点：

- 偏稳
- 适合作为当前默认主线
- 最适合配新版 `fine_recall / recall` sweep

### 路线二：mid + 分集训 + fullset

目标：

- 先利用分集/分级训练拿到更干净的中间权重
- 再接一段 fullset，把分集的干净和全集的覆盖拼起来

对应代码：

- Stage1：`split_bridge_stage1`
- Stage2：`split_bridge_stage2_fullset`

核心特点：

- 这是当前最标准的“桥接线”
- Stage1 负责干净
- Stage2 负责覆盖
- 是否优于路线一，要看真实 val / sweep / 榜单反馈

### 路线三：路线二 Stage1 + unfreeze encoder

目标：

- 在路线二 Stage1 的 best 权重上，做小范围 image encoder 解冻诊断
- 不解冻 text encoder
- 不做全量 backbone 解冻

对应代码：

- `train_esam_cclip_11.py`
- `--unfreeze_image_mode`
- 推荐 preset：`partial_unfreeze_lastnorm`

当前建议：

- 先只跑 `last_norm`
- 先跑 1 个 epoch 看验证集反应
- 这条线不是默认主线，而是“看有没有额外增益”的诊断线

### 路线四：新 sweep + 两个最好 recall 权重做平均

目标：

- 不改训练结构，直接利用已有候选权重做后处理增强
- 所有训练路线都先跑新版 sweep
- 从 recall 结果最好的两个候选权重里再做 checkpoint averaging

对应代码：

- `sweep_thresholds_11.py`
- `tools/average_checkpoints.py`

推荐做法：

1. 所有候选权重先跑 `recall`
2. 最强的 1 到 2 个再跑 `fine_recall`
3. 选 recall/fine_recall 表现最好的两个权重做平均
4. 对平均后的权重再跑一遍 sweep，重新写回 `sam3.pt`

这条线的本质：

- 不改训练逻辑
- 风险低
- 很适合作为“提交前最后一轮抠分”

### 路线五：更新推理脚本

目标：

- 不改 `predictions.json` 语义
- 不改 RLE 格式
- 在官方单权重提交框架下，做低风险推理优化

当前推理脚本已经支持：

- prompt alias normalize
- 更完整的 alias 映射
- `topk_components`
- `rare_empty_fallback`，默认关闭
- 更紧凑的输出写盘
- 更清晰的 debug summary

对应代码：

- `src/ESAM-CCLIP-11/inference.py`

结论：

- 现在所有路线最终都应该尽量统一用这版新 `inference.py`
- 这样对比更干净，变量更少

## 2. 每条路线怎么理解

### 路线一适合什么情况

- 你已经有一个比较强的 `lite` 底座
- 你不想冒太大训练风险
- 你更想先靠 fullset + 新 sweep + 新 inference 稳定吃分

### 路线二适合什么情况

- 你怀疑分集训练确实带来了更干净的 rare / hard case 学习
- 但单纯分集权重又不够强
- 所以希望通过 Stage1 + Stage2 折中

### 路线三适合什么情况

- 你已经拿到了一个不错的 Stage1 权重
- 想验证“轻微放开 image encoder”能不能比纯 decoder 再多一点收益
- 但不想直接冒全量 backbone 解冻的风险

### 路线四适合什么情况

- 你已经有多条候选路线跑完
- 不想再开太多新训练
- 想直接在现有 best 权重上做后处理和 checkpoint averaging 抠分

## 3. 当前优先级建议

当前建议的优先级是：

1. 路线一：`lite + fullset`
2. 路线二：`mid / split -> fullset`
3. 路线四：新版 sweep + averaging
4. 路线三：Stage1 + partial unfreeze

原因：

- 路线一最稳
- 路线二最值得验证
- 路线四最省风险
- 路线三更像“诊断增强线”，不是默认主线

## 4. 当前推荐执行顺序

推荐按下面顺序跑：

1. 先训路线一和路线二
2. 各自跑 `recall` sweep
3. 最强候选再跑 `fine_recall`
4. 比较路线一和路线二的 best recall/fine_recall
5. 选两个最强候选做 checkpoint averaging
6. 对平均后的权重再跑一次新版 sweep
7. 最后统一用新版 `inference.py`

## 5. 现在你应该怎么看日志和结果

### 训练结果

重点看：

- `mIoU_all11`
- `mIoU_old5`
- `mIoU_rare`
- `pos_mIoU`

### sweep 结果

重点看：

- `best_metric`
- 每类 `best_threshold`
- 每类 `best_min_area`
- 每类 `best_topk_components`
- 每类 `precision / recall / pred_area / gt_area`

### 解冻实验

重点看：

- `text_encoder trainable params = 0`
- `image_encoder trainable params > 0`
- `image_encoder trainable params <= 5M`
- optimizer 里同时有 `decoder` 和 `image` 两组
- 1 epoch 后 val 指标是否立刻掉点

## 6. 最后结论

现在这套 ESAM-CCLIP-11 代码，不再是单一一条训练线，而是：

- 路线一：`lite + fullset`
- 路线二：`mid + 分集训 + fullset`
- 路线三：`路线二 stage1 + partial unfreeze image encoder`
- 路线四：`新版 sweep + recall 最强两权重平均`
- 路线五：`统一使用新版 inference.py`

如果只看当前最值得投入资源的方向：

- 主线继续押路线一
- 次主线验证路线二
- 末端抠分重点放在路线四
- 路线三只做小规模诊断，不建议一开始重仓
