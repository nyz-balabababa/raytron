# Hanxue 修改与整条线路说明

## 1. 路线定位

`src/hanxue` 当前是一条和 `src/train.clipseg-v1` 做同协议对比的学生模型路线，不是官方原生 `EfficientSAM` 全链路。

当前真实模型结构是：

```text
输入图像
-> InfraredPromptDataset
-> EfficientSAM ViT-T image encoder
-> Chinese-CLIP text encoder
-> FiLMFusionDecoder
-> 单通道分割 logits
```

对应文件：

- [config_hanxue.py](D:/nyz/raytron_project/src/hanxue/config_hanxue.py)
- [data/dataset.py](D:/nyz/raytron_project/src/hanxue/data/dataset.py)
- [models/image_encoder.py](D:/nyz/raytron_project/src/hanxue/models/image_encoder.py)
- [models/text_encoder.py](D:/nyz/raytron_project/src/hanxue/models/text_encoder.py)
- [models/fusion_decoder.py](D:/nyz/raytron_project/src/hanxue/models/fusion_decoder.py)
- [models/custom_sam_model.py](D:/nyz/raytron_project/src/hanxue/models/custom_sam_model.py)
- [train.py](D:/nyz/raytron_project/src/hanxue/train.py)
- [inference.py](D:/nyz/raytron_project/src/hanxue/inference.py)

顶层训练接口没有改：


## 4. Dataset 整条链路

文件：[data/dataset.py](D:/nyz/raytron_project/src/hanxue/data/dataset.py)

### 4.1 样本构造

`InfraredPromptDataset` 做的事是：

1. 读取 teacher 伪标签 JSON
2. 按 `train_list.txt` / `val_list.txt` 过滤允许图片
3. 对每张图的每个 prompt 拆成独立样本
4. `hit=true` 时构造正样本
5. `hit=false` 时按 `NEGATIVE_SAMPLE_RATIO` 抽负样本
6. 正样本的 RLE 解码后缓存成 PNG

当前负样本策略：

```python
INCLUDE_NEGATIVE_SAMPLES = True
NEGATIVE_SAMPLE_RATIO = 0.15
NEGATIVE_SAMPLE_WEIGHT = 0.30
```

当前稀有类过采样：

```python
RARE_OVERSAMPLE = {
    "animal": 3,
}
```

### 4.2 图像预处理

Dataset 内部图像链路是：

```text
读图
-> 伪彩图转灰度
-> 黑热/白热统一
-> 按统计量动态 CLAHE / 去噪 / 锐化
-> letterbox 到 1024x1024
-> gray 复制成 3 通道
-> /255.0 变成 0~1 float
```

也就是说，Dataset 输出给模型前的图像是：

```text
0~1 RGB tensor
```

Dataset 没有再做 `ImageNet mean/std normalize`。真正的标准化是在 [image_encoder.py](D:/nyz/raytron_project/src/hanxue/models/image_encoder.py) 里做的：

```python
x = (x - pixel_mean) / pixel_std
```

所以当前没有“dataset 二次 normalize”的问题。

### 4.3 文本增强与类别字段分离

当前 `hanxue` 已经支持 prompt augmentation，且和 `clipseg-v1` 的增强表一致。

训练时逻辑是：

1. 先拿原始类别名 `sample["prompt"]`
2. 命中 `PROMPT_AUG_PROB=0.5` 时，替换为增强文本
3. tokenizer 吃增强后的文本
4. 同时保留原始类别名给类别控制逻辑

Dataset 返回的关键字段现在是：

```python
{
    "prompt": sample["prompt"],
    "class_name": sample["prompt"],
    "orig_prompt": sample["prompt"],
    "prompt_text": prompt,
}
```

它们的语义分别是：

- `prompt`：原始类别名，固定是五类之一
- `class_name`：原始类别名，给训练控制用
- `orig_prompt`：原始类别名，备用字段
- `prompt_text`：真正送 tokenizer 的文本，训练时可能是增强文本

这一点很关键：

- 模型吃增强后的文本
- 所有按类别分流、查表、统计的逻辑吃原始类别名

## 5. 模型链路说明

### 5.1 图像编码器

文件：[models/image_encoder.py](D:/nyz/raytron_project/src/hanxue/models/image_encoder.py)

当前只保留 `EfficientSAM ViT-T` 的 `image_encoder` 部分，不接它原生的 `prompt encoder` 和 `mask decoder`。

这次补的安全措施有三类：

1. 权重路径从配置项 `EFFICIENT_SAM_CKPT` 读取，不再靠硬编码。
2. 权重不存在直接 `FileNotFoundError`，不再静默随机初始化。
3. 单独检查 `image_encoder.*` 的缺失键；如果缺得太多，直接报错停止训练。

### 5.2 文本编码器

文件：[models/text_encoder.py](D:/nyz/raytron_project/src/hanxue/models/text_encoder.py)

当前文本端是本地 `ChineseCLIPTextModel`：

- 优先从本地目录读取
- 如果 `pytorch_model.bin` 存在，额外手工抽取 `text_model.*` 权重
- 所有文本参数冻结
- 外部即使调用 `model.train()`，文本编码器也强制保持 `eval()`

这意味着当前文本编码器是稳定的，不参与训练更新，也不会因为 dropout 导致训练和验证口径漂移。

### 5.3 FiLM 解码器

文件：[models/fusion_decoder.py](D:/nyz/raytron_project/src/hanxue/models/fusion_decoder.py)

当前 FiLM 解码器做的事情是：

1. 用文本全局特征生成 `gamma` 和 `beta`
2. 对图像特征做 FiLM 调制
3. 走卷积头输出 1 通道 logits
4. 双线性插值回目标尺寸

这次加的稳定化改动是：

```python
nn.init.zeros_(self.film_projection.weight)
nn.init.zeros_(self.film_projection.bias)
```

作用是让训练初始阶段尽量接近“先只看图像特征，再逐渐学文本调制”，避免一开始就把预训练图像特征扰乱得太狠。

### 5.4 顶层模型

文件：[models/custom_sam_model.py](D:/nyz/raytron_project/src/hanxue/models/custom_sam_model.py)

顶层模型仍然只是把三段拼起来：

```text
PureImageEncoder
+ FreezeTextEncoder
+ FiLMFusionDecoder
```

没有改 forward 协议，也没有新增额外分支。

## 6. 训练链路说明

文件：[train.py](D:/nyz/raytron_project/src/hanxue/train.py)

### 6.1 train_one_epoch 现在的行为

训练时当前的输入分工已经分开：

```python
text_prompts -> tokenizer 后的 input_ids / attention_mask -> 给模型
class_prompts = batch["class_name"] -> 给类别相关控制
```

虽然 `train.py` 里实际拿的是编码后的 token 张量，但这些 token 来自 Dataset 中的 `prompt_text`，也就是增强文本。

类别控制则用原始类别名 `batch["class_name"]`，不会因为增强成 `"trees and vegetation"`、`"建筑物或房屋结构"` 之类的文本而查表失败。

### 6.2 主损失

当前主损失仍然是：

```python
SemanticSegLoss(
    bce_weight=1.0,
    dice_weight=1.0,
    focal_weight=0.0,
)
```

也就是：

```text
主损失 = BCE + Dice
```

原来的全局 Focal 项没有关掉代码实现，但权重已经置为 `0.0`，所以当前不参与总损失。

### 6.3 class-aware focal 辅助项

在主损失之外，当前额外加了一个按类 focal 辅助项：

```text
总损失 = BCE + Dice + class-aware focal aux
```

当前参数：

```python
FOCAL_GAMMA = 1.5
FOCAL_POS_FACTOR = 1.0
FOCAL_NEG_FACTOR = 0.25

CLASS_FOCAL_WEIGHT = {
    "person": 0.25,
    "car": 0.0,
    "building": 0.55,
    "tree": 0.55,
    "animal": 0.45,
}
```

当前逻辑不是粗暴全图平均，而是：

1. 算逐像素 focal map
2. 分开正区域和负区域
3. 正样本同时看前景和背景，但背景项降权
4. 负样本只保留背景项
5. 再乘类别权重和样本权重

这样改的目的很明确：

- 小目标不会被大面积背景彻底淹没
- `building/tree` 能得到更强的轮廓约束
- 负样本还能抑制误检，但不会反客为主

### 6.4 sample weight 修正

之前有个明显问题：如果直接做

```python
sample_weight.clamp(min=LOSS_WEIGHT_FLOOR)
```

会把负样本权重 `0.30` 也强行抬到 `0.70`。

现在已经改成：

- 正样本：`clamp(min=LOSS_WEIGHT_FLOOR)`
- 负样本：保持原值

所以当前 `NEGATIVE_SAMPLE_WEIGHT = 0.30` 在 focal 辅助项里是真正生效的。

### 6.5 optimizer 分组

当前优化器按参数来源做了明确分组：

- `img_encoder` 相关参数走 `IMAGE_LR = 1e-5`
- `decoder` / `fusion_decoder` 相关参数走 `DECODER_LR = 1e-4`
- 如果文本编码器有意外可训练参数，单独分组且学习率压到 `1e-6`
- 其他未识别参数归到 `other`，同时打印 warning

目的就是避免：

- 图像 backbone 被高学习率打坏
- 文本编码器意外混进大 lr

### 6.6 调度与稳定项

当前训练稳定项：

```python
WARMUP_EPOCHS = 2
MIN_LR_RATIO = 0.01
GRAD_CLIP = 1.0
WEIGHT_DECAY = 0.03
```

调度器仍然是 warmup + cosine。

## 7. 验证、指标和 checkpoint

### 7.1 验证口径

`validate()` 当前按类阈值做二值化，并统计：

- `iou/overall`
- `dice/overall`
- 每类 `iou/<class>`
- `iou/pos_only`
- `dice/pos_only`

其中：

- `overall` 包含正样本和负样本
- `pos_only` 只统计真值里有前景的样本

### 7.2 checkpoint 策略

当前输出：

- `last.pt`
- `best.pt`
- `best_pos.pt`
- `results.csv`

保存口径：

- `best.pt` 按 `iou/overall`
- `best_pos.pt` 按 `iou/pos_only`

这样你可以同时看两件事：

1. 模型整体拒识和分割综合表现
2. 模型在真正正样本上的纯分割能力

### 7.3 运行名

为了避免接上旧 checkpoint，当前运行名已改成：

```python
RUN_NAME = "efficientsam_easy_v1"
```

### 8.2 推理线

- 如果训练提升了，后续评估时优先换 checkpoint，不要先怀疑推理协议

## 9. 当前版本的结论

当前 `hanxue` 这条线已经从“能跑的自定义 EfficientSAM 学生模型”收紧成了“适合和 `clipseg-v1` 做同 teacher、同任务、同评估协议对比”的版本。

当前核心特征是：

- 数据入口对齐旧 teacher
- 模型结构不变，仍是 `EfficientSAM image encoder + Chinese-CLIP + FiLM`
- 文本编码吃增强后的 prompt
- 所有类别相关训练控制吃原始类别名
- 负样本仍保留，但不会在 focal 中被错误抬权
- 同时保留 `overall best` 和 `pos_only best` 两套 checkpoint

如果后面继续扩展，建议把“接 EfficientSAM 原生 `mask_decoder`”单独开新路线，不要污染这条现有可比性较强的对照线。
