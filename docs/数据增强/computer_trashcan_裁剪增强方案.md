# computer / trash can 裁剪增强方案

## 1. 目标

本方案用于替代效果不稳定的离线 Copy-Paste，针对 `computer` 和 `trash can` 做**正样本裁剪增强**，并可选生成少量**纯背景负样本裁剪**。

核心思路：

- 从原始正样本图出发
- 围绕目标裁一个更小的 patch
- 让目标在 patch 中相对更大
- 同步生成新的图片、标签、`pred_json`

适用场景：

- `trash can`：目标偏小、在整图中不显著、容易被背景淹没
- `computer`：目标偏小，但仍需要保留设备上下文

---

## 2. 方案原则

与 Copy-Paste 不同，裁剪增强不做跨图拼接，只在原图内重组训练样本。

优点：

- 不破坏红外热分布
- 不引入拼接边界
- 对 `world` 和后续 `clipseg` 都更自然

注意：

- 默认以**正样本增强**为主
- 不用于验证集
- 生成出的样本应当作为新的训练样本独立保存
- 纯背景负样本仅作为可选补充，不建议一开始大量加入

---

## 3. trash can 裁剪增强

### 3.1 适用样本

只对满足以下条件的样本做增强：

- `trash can hit = true`
- `score >= 0.65`
- 目标不是超大实例
- 目标不贴边

不建议增强：

- 已经很大的 `trash can`
- 被截断或贴图像边缘的 `trash can`
- 伪标签明显覆盖整块背景的样本

### 3.2 裁剪策略

以 `trash can` 的 bbox 为中心裁 patch。

建议参数：

- 外扩倍数：`2.0x ~ 3.0x`
- 推荐起点：`2.5x`
- 目标在 patch 中占比较高
- 裁剪后目标占 patch 面积比例不应过低
- 一个 patch 只围绕一个主 `trash can`

设计原因：

- `trash can` 对上下文依赖相对较弱
- 可以裁得更紧一些
- 重点是让目标在 patch 中更显著

### 3.3 第一轮推荐规模

- 新增样本数：`100 ~ 200`
- 推荐起点：`150`

---

## 4. computer 裁剪增强

### 4.1 适用样本

只对满足以下条件的样本做增强：

- `computer hit = true`
- `score >= 0.60`
- 目标偏小但清晰
- 伪标签主要覆盖设备本体，而不是整块大背景

不建议增强：

- 大面积面板或整块设备区
- 目标贴边
- 裁紧后只会剩一个亮矩形块的样本

### 4.2 裁剪策略

以 `computer` 的 bbox 为中心裁 patch，但要保留更多上下文。

建议参数：

- 外扩倍数：`3.0x ~ 4.5x`
- 推荐起点：`3.5x`
- 保留更多 surrounding context
- 如果可视化后发现 `computer` 在 patch 中仍然偏小，可考虑收紧到 `2.0x ~ 3.0x`

设计原因：

- `computer` 比 `trash can` 更依赖上下文
- 裁得太紧时，容易退化成“亮矩形纹理”
- 需要保留设备、桌面、控制台、墙面等线索

### 4.3 第一轮推荐规模

- 新增样本数：`50 ~ 120`
- 推荐起点：`80`

---

## 5. 标签同步策略

每张裁剪图都应同步生成一份完整训练样本：

- 新图片
- 新 bbox / mask
- 新 `pred_json` 记录

建议规则：

- 保留裁剪窗口内的有效目标标签
- 裁剪窗口外的目标直接丢弃
- 被裁断过多的实例丢弃
- 对主目标额外检查“裁剪后占整张 patch 的面积比例”，避免目标仍然过小
- `world` 训练使用 bbox
- `clipseg` 后续保留 mask / RLE

这意味着裁剪增强不是简单“截小图”，而是要生成新的标准训练样本。

---

## 6. 与 Copy-Paste 的区别

裁剪增强：

- 保真放大
- 不改图像热分布
- 更适合当前 `world` 线验证

Copy-Paste：

- 属于跨图合成
- 易引入分布偏移
- 前期实验中已经验证对 `v4` 收益不稳定

因此后续实验命名应与 Copy-Paste 分开，例如：

- `crop_trashcan`
- `crop_computer`

不要与 `copy_paste` 混用命名。

---

## 7. 当前脚本行为

当前 `offline_crop_tail.py` 已实现以下约束：

- 正样本只从 `d5&7` 伪标签命中的高质量实例中抽取
- 裁剪框仍以目标 bbox 为中心，但会做轻微中心抖动
- 主目标必须同时满足：
  - 原实例保留比例达标
  - 裁剪后 mask 像素数不低于最小阈值
  - 裁剪后目标占 patch 面积比例不低于类别阈值
- 非主目标标签不会无脑继承，而是按连通域逐实例检查保留比例，避免把裁残碎片直接写回
- 导出的 YOLO 标签类顺序固定对齐 `world v4`：
  - `computer`
  - `trash can`
- 额外输出 `source_usage.csv`，统计每个源实例被重复使用的次数
- 额外输出 `preview/`，保存若干张“原图裁剪框 + 裁后 patch + mask 叠加”的可视化结果

这样做的目的是：

- 防止“裁了等于没裁”，目标在新图里依然太小
- 防止某个低质量源实例被重复采样过多次
- 防止生成样本与 `world v4` 的类 id 对不上

---

## 8. 可选纯背景负样本

脚本支持通过 `--num-neg-samples` 从**完全无目标**的图像中随机裁若干 patch，生成：

- 新图片
- 空的 YOLO 标签
- 所有 prompt 都为 `hit: False` 的 `pred_json` 记录

用途：

- 补充“局部背景拒识”能力
- 让模型不仅学会拒绝整张空图，也学会拒绝局部背景块

建议：

- 默认保持 `0`
- 第一轮只做少量试验，例如正样本数的 `0.2x ~ 0.5x`
- 不建议一开始把纯背景 patch 加得比正样本还多

原因：

- 当前 `world v4` 本身已经有整图级空标签负样本采样
- 局部纯背景 patch 更像额外的 hard negative 补充，而不是当前主增强来源

---

## 9. 推荐实验顺序

建议按以下顺序推进：

1. 先只做 `trash can` 裁剪增强
2. 在 `v4` 上验证是否优于当前最佳基线
3. 如果 `trash can` 有正信号，再加入 `computer`
4. 不要一开始同时大量增强两个类

当前推荐起点：

- `trash can`
  - `score >= 0.65`
  - 外扩倍数 `2.5x`
  - 新增 `150` 张
- `computer`
  - `score >= 0.60`
  - 外扩倍数 `3.5x`
  - 新增 `80` 张

---

## 10. 额外输出文件

除增强图、标签和 merged `pred_json` 外，当前脚本还会输出：

- `manifest.csv`
  - 每张新样本的来源图、裁剪框、保留比例、目标占比、样本类型
- `source_usage.csv`
  - 每个源实例被成功复用的次数

其中 `source_usage.csv` 主要用于排查：

- 是否某个源实例被重复使用太多次
- 是否训练集被少数高分或低质量样本支配

另外，`preview/` 目录用于快速人工抽查：

- 裁剪框是否合理
- 主目标在 patch 中是否足够显著
- 非主目标是否被裁残后错误保留

默认导出少量预览图，可通过：

- `--num-preview`

控制生成数量。

---

## 11. 当前结论

对于当前 `YOLO-World + FastSAM v4` 路线：

- `trash can` 优先做裁剪增强
- `computer` 可作为第二阶段补充
- `cable connector` 当前已不再作为重点增强对象

如果后续继续做 `person@data1` 极小目标专项，应单独设计，不与本方案混用。
