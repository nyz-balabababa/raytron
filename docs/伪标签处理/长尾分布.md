可以做，而且我建议你**现在同步从伪标签挖稀有类**是对的。核心思路不是“发现一堆新类就合进主模型”，而是：

> **先挖候选稀有类 → 单独验证它能不能学 → 训练稀有类 specialist → 推理时和五大类主模型融合。**

这样不会让 computer / trash can 继续被 person、tree、building、animal、car 淹没。

------

## 我建议的可实现方案

### 1. 先别直接扩成“大多类训练”，先做“稀有类候选池”

你现在已知：

- 五大类：`person / tree / building / animal / car`
- 已知可学稀有类：`computer / trash can`
- 问题：稀有类和五大类一起训会被频次压死
- 新现象：引入负样本后 recall 上来了，但 precision 略降

所以第一步应该是：**用 open-vocab teacher 去扫更多可能的小类**，但只把“能稳定打出来”的类留下。

候选类可以先从这些方向试：

```txt
computer, laptop, monitor, screen, keyboard
trash can, dustbin, garbage bin, bin

chair, table, bench
bicycle, motorcycle, bus, truck
traffic light, street light, pole, sign, billboard
fence, window, door
bag, backpack, suitcase
umbrella, cone
```

注意：这里不是说这些都要加入训练，而是先作为 **prompt bank** 扫一遍，统计哪些类真的存在、teacher 是否稳定。

------

### 2. 每个候选类先做“可学性筛选”

每个类不要凭感觉加入，建议做一个小统计表：

| 指标                | 用途               | 建议标准                                |
| ------------------- | ------------------ | --------------------------------------- |
| 伪标签数量          | 判断是否太稀       | 至少 50 个实例更稳，极稀有类 20+ 也能试 |
| 图片覆盖数          | 防止全来自少数图片 | 至少 20 张图以上                        |
| teacher 平均置信度  | 判断伪标签质量     | 不能全靠低分捞出来                      |
| mask 面积分布       | 排除奇怪噪声       | 不要全是 5×5 小点或整张大块             |
| top-50 人工抽查精度 | 最关键             | 目测 70% 以上才值得训                   |

这里我会比较激进一点：
**稀有类不要求数量特别多，但要求 top 样本干净。** 比如 `computer`、`trash can` 如果 top 100 很准，就可以单独训；如果某类 500 个伪标签但一半都是错的，反而先别碰。

------

### 3. 建一个 rare-only 训练集，不要一开始合进五大类

我建议新建一个稀有类 manifest，比如：

```txt
rare_classes = [
  "computer",
  "trash can",
  "laptop",
  "monitor",
  "chair",
  "bicycle",
  ...
]
```

但训练时先分两档：

**A 档：已知可学类**

```txt
computer
trash can
```

**B 档：新挖候选类**

```txt
laptop / monitor / chair / bicycle / sign / pole ...
```

先训一个 **rare-specialist 模型**，只负责稀有类，不和五大类抢 loss。

这个模型的数据结构建议：

```txt
正样本：rare 类伪标签
负样本：不含该 rare 类的图片-prompt 对
困难负样本：五大类里容易误触的区域
```

例如：

- `computer` 的困难负样本：window、sign、car window、building facade
- `trash can` 的困难负样本：tree trunk、pole、car tire、box
- `chair/table` 的困难负样本：building/window/fence

这样比普通随机负样本更有用。

------

### 4. 负样本比例不要太大，rare-only 阶段建议更温和

你现在引入负样本后 recall 上升、precision 下降，说明模型可能变得更“敢报”。这个现象不一定坏，因为榜单如果更怕漏检，recall 上升可能是赚的。

但 rare-only 模型我建议这样设：

```txt
正样本 : 负样本 ≈ 1 : 1 或 1 : 1.5
```

不要一上来搞太多负样本，比如 1:3、1:5，这会让稀有类又被压住。

更推荐：

```txt
普通负样本 70%
困难负样本 30%
```

而不是全随机负样本。

------

### 5. 推理阶段做“双模型融合”，别把主模型推翻

最终推理建议是：

```txt
五大类主模型：负责 person/tree/building/animal/car
rare-specialist：负责 computer/trash can/新稀有类
最后按类别合并结果
```

融合策略可以简单点：

1. 五大类沿用当前最优模型。
2. 稀有类 specialist 单独输出。
3. 如果 rare mask 和五大类 mask 大面积重叠：
   - rare 置信度高，保留 rare；
   - rare 置信度低，被五大类覆盖则删除。
4. rare 类阈值单独调，不跟五大类共用。

稀有类阈值建议先偏低：

```txt
computer: 0.45~0.55
trash can: 0.40~0.50
新候选类: 0.50~0.60 起步
```

然后看验证集 precision 再往上调。

------

## 我觉得当前最值得做的路线

按优先级排：

### 第一优先级：computer + trash can 单独训

这是最稳的，因为你已经知道它们“小数据能学到”。现在的问题不是不可学，而是被大类淹没。

做法：

```txt
rare_v1 = computer + trash can
训练 rare-only specialist
推理时和当前最强五大类模型融合
```

这个最可能快速带来收益。

------

### 第二优先级：扩展同义词，不是立刻扩展新语义类

比如 computer 不只用 `computer`，还可以扫：

```txt
computer
laptop
monitor
screen
keyboard
desktop computer
```

trash can 也可以扫：

```txt
trash can
garbage bin
dustbin
waste bin
bin
```

最后训练标签可以先合并回：

```txt
computer 系 → computer
trash can 系 → trash can
```

这比新增很多类别更稳。
因为你真正想提升的是稀有目标召回，不一定非要输出更细的新类。

------

### 第三优先级：再挖真正新类

等你发实验数据后，再看哪些类有价值。候选新类我会重点看：

```txt
chair / table / bicycle / motorcycle / sign / pole / traffic light / bench
```

但这些要谨慎，因为它们有些可能和五大类语义冲突，或者评测根本不奖励。

------

你稍后发实验结果的话，最好包含：

```

我拿到这些之后，可以直接帮你判断：

哪些类应该丢掉
负样本比例要不要降
rare 模型推理阈值怎么设

```

我现在的判断是：**先做 computer + trash can + 同义词扩充的 rare-specialist，别急着把所有新类塞进主训练。** 这条路线风险最低、见效最快，也最符合你现在时间紧的情况。
