会，**500 随机小样本很容易误判长尾类**。

比如 `bicycle / backpack / animal / suitcase` 这种，如果真实分布本来就是 1% 以下，随机 500 张没抽到很正常，不能说明这个类没价值。
所以之前 500 小样本的结论只能理解成：

> **抽到的这批里面，truck / bus / street light 比较干净；
> 但没出现或很少出现的类，不能直接判死刑。**

------

## 同义词到底怎么用收益更大？

直接结论：

> **先用同义词参与伪标签生成和合并，收益通常大于只在训练脚本里做 prompt 扩展。**
> 但最稳的是：**伪标签阶段用同义词挖目标，训练阶段继续做 prompt 扩展。**

也就是不是二选一，而是：

```txt
生成伪标签时：
laptop / monitor / screen / keyboard 都去扫

训练时：
这些都合并成 computer 标签
然后 prompt 随机使用 computer / laptop / monitor / screen / keyboard
```

------

## 为什么“伪标签阶段加同义词”收益更大？

因为训练脚本里的 prompt 扩展只能改变文本输入，**不能凭空增加正样本 mask**。

举个例子：

如果原来只用：

```txt
computer
```

生成伪标签，它可能漏掉很多：

```txt
laptop
monitor
screen
keyboard
```

这时你训练阶段再加 prompt 扩展：

```txt
computer / laptop / monitor
```

模型看到的还是原来那批 mask，漏掉的目标仍然没进训练。

但是如果伪标签阶段就用：

```txt
computer
laptop
monitor
screen
keyboard
```

去扫，可能会补出更多正样本。
这对长尾 recall 的提升更直接。

所以收益排序我会这样排：

```txt
1. 同义词生成伪标签 + 合并去重
2. 训练脚本 prompt 扩展
3. 简单重复同义词样本
```

------

## 但有一个坑：不要把同一个目标重复训练很多次

如果 `computer / laptop / monitor / screen` 检出来的是同一个 mask，你不能全都作为独立样本直接塞进去。
否则等于把某些噪声或重复目标过采样，会让模型偏。

正确做法是：

```txt
同义词检测结果先合并
重叠高的只保留一个 mask
训练时再随机换 prompt
```

比如：

```txt
computer 检出 A
laptop 检出 A
monitor 检出 A

最后训练样本只保留一个 A
label = computer
prompt_pool = ["computer", "laptop", "monitor", "screen"]
```

训练时每次随机取一个 prompt：

```txt
这次用 laptop
下次用 computer
下次用 monitor
```

这样收益比重复塞 3 份更稳。

------

## 具体合并规则建议

对同义词结果做 IoU 去重：

```python
if iou(mask_a, mask_b) > 0.6:
    keep higher_score_one
```

如果是小目标，也可以加 containment：

```python
contain = intersection / min(area_a, area_b)

if contain > 0.8:
    keep higher_score_one
```

然后统一映射：

```python
MERGE_TO_CLASS = {
    "computer": "computer",
    "laptop": "computer",
    "monitor": "computer",
    "screen": "computer",
    "keyboard": "computer",

    "trash can": "trash can",
    "dustbin": "trash can",
    "garbage bin": "trash can",
    "bin": "trash can",

    "truck": "car",
    "bus": "car",
    "bicycle": "car",
    "motorcycle": "car",

    "lion": "animal",
    "bird": "animal",
    "bear": "animal",
    "rhinoceros": "animal",

    "door": "building",
    "window": "building",
    "fence": "building",
    "house": "building",
}
```

------

## 如果同义词得分差不多，怎么判断该不该都加？

不要只看分数，要看它们是不是检测到**相同目标**。

### 情况 1：同义词检出来高度重合

比如：

```txt
computer / laptop / monitor 检出来基本是同一个区域
```

那说明同义词主要是文本增强，不是新增目标。

这时：

```txt
不要重复加样本
更适合训练阶段 prompt 扩展
```

------

### 情况 2：同义词能补出不同目标

比如：

```txt
computer 只检出台式机
laptop 检出笔记本
monitor 检出显示器
keyboard 检出键盘
```

这时：

```txt
伪标签阶段合并收益更大
```

因为它真的增加了 rare 正样本。

------

### 情况 3：同义词检出来很多奇怪东西

比如：

```txt
screen 检出窗户
bin 检出各种小黑块
pole 检出树干
traffic light 检出亮点
```

这种不要直接进训练。
只能作为探索结果，后面强过滤。

------

## 对你现在最建议的做法

### 第一优先级：同义词增强已知稀有类

这个最值得：

```txt
computer:
computer / laptop / monitor / screen / keyboard

trash can:
trash can / dustbin / garbage bin / waste bin / bin
```

做法：

```txt
1. 全数据扫这些 prompt
2. 同义词结果合并去重
3. 映射成 computer / trash can
4. 从 clipseg best.pt 做 rare-balanced finetune
5. 训练脚本里保留 prompt 扩展
```

这个收益大概率比只在训练脚本里加 prompt 扩展更大。

------

### 第二优先级：五大类子类增强

可以用：

```txt
truck / bus / bicycle / motorcycle → car
lion / bird / bear / rhinoceros → animal
door / window / fence / house → building
```

但这里要谨慎一点。
因为 `car / building / animal` 本来已经有样本，子类增强的收益不一定比 `computer / trash can` 明显。

------

## 500 小样本应该怎么继续用？

不要用它判断“这个类有没有”。
它适合判断：

```txt
某个 prompt 一旦命中，伪标签干不干净
```

更合理的流程是：

```txt
1. 先全数据低阈值扫一遍，找每个 prompt 的 top 样本
2. 每类看 top 50 可视化
3. 再决定这个类是否进入训练
```

不要随机 500 张判断长尾类是否存在。
应该改成：

```txt
每个 prompt 单独取 score top 100~300
人工看 top 样本质量
```

这样不会因为随机样本没抽到而误杀这个类。

------

## 最终建议

你的问题里两个方案，优先级是：

```txt
更大收益：
同义词生成伪标签 + 合并成统一类别

更稳辅助：
训练脚本 prompt 扩展

不推荐：
同义词结果不去重，直接重复塞进训练
```

所以我建议你现在这样做：

```txt
伪标签阶段：
computer/laptop/monitor/screen/keyboard 全扫
trash can/dustbin/garbage bin/bin 全扫
合并去重，统一成 computer/trash can

训练阶段：
仍然保留 prompt 扩展
同一个 mask 每次随机换同义词 prompt
```

一句话：**同义词先拿来“挖更多正样本”，再拿来“增强文本鲁棒性”。前者对长尾 recall 的收益更大。**

那就**不要硬映射**。近义词映射不好时，强行合并到 `computer / trash can / car / building` 里，收益会变成污染，尤其会让主模型 precision 掉。

我建议按这个规则处理：

## 1. 近义词效果不好，就分三类处理

### A 类：检得准、能补目标 → 参与正样本

比如：

```txt
laptop 检出来确实是电脑类
monitor 检出来确实是屏幕/电脑设备
dustbin 检出来确实是垃圾桶
```

这种才可以：

```txt
laptop / monitor → computer
dustbin / garbage bin → trash can
```

------

### B 类：检出来不准，但误检有规律 → 做 hard negative

比如：

```txt
screen 经常检成 window
bin 经常检成小黑块
pole 经常检成 tree trunk
traffic light 经常检成亮点/窗户
```

这种不要当正样本。
但它很有价值，可以反过来做负样本：

```txt
screen 误检 window → computer 的 hard negative
bin 误检黑块 → trash can 的 hard negative
pole 误检树干 → street light / pole 的 hard negative
```

也就是说：

> **近义词不好，不代表没用；它可以用来告诉模型“这些不是目标”。**

------

### C 类：检得乱、没有规律 → 直接丢

如果一个 prompt 输出：

```txt
到处乱框
score 分布也不稳定
top 样本也不准
```

那就不要进训练，也不要做负样本。直接丢，别浪费时间。

------

## 2. 不要因为“近义词”就默认能合并

你现在应该从：

```python
MERGE_TO_CLASS = {
    "laptop": "computer",
    "monitor": "computer",
    "screen": "computer",
    "keyboard": "computer",
}
```

改成更保守的结构：

```python
PROMPT_POLICY = {
    "laptop": {
        "target": "computer",
        "use_as": "positive",
        "min_score": 0.50,
    },
    "monitor": {
        "target": "computer",
        "use_as": "positive",
        "min_score": 0.52,
    },
    "screen": {
        "target": "computer",
        "use_as": "hard_negative",
        "min_score": 0.58,
    },
    "keyboard": {
        "target": "computer",
        "use_as": "positive_if_clean",
        "min_score": 0.50,
    },
}
```

也就是每个 prompt 单独决定：

```txt
正样本 / 困难负样本 / 暂时丢弃
```

------

## 3. 对 computer 系，我会这样判断

### 比较可能能用

```txt
laptop → computer
monitor → computer
keyboard → computer，谨慎
```

### 风险较高

```txt
screen → 很容易检成 window / billboard / bright area
```

所以 `screen` 如果效果不好，不要映射成 computer，改成：

```txt
screen → computer 的 hard negative
```

或者直接只用于探索。

------

## 4. 对 trash can 系，我会这样判断

### 比较可能能用

```txt
trash can
dustbin
garbage bin
```

### 风险很高

```txt
bin
```

`bin` 太泛了，可能检成：

```txt
箱子
小黑块
桶状物
建筑局部
车辆部件
```

所以如果 `bin` 映射不好，直接不要当正样本。

建议：

```txt
trash can / dustbin / garbage bin → trash can 正样本
bin → 先不用，或者只取 top very clean 样本
```

------

## 5. 如果同义词整体都不好，说明这条路线该收缩

那就不要继续扩很多类，而是回到最稳路线：

```txt
只保留原始 computer
只保留原始 trash can
少量高置信 top 样本
加 hard negative
做 rare-balanced 微调
```

这比乱加同义词更稳。

也就是：

```txt
不要追求多 prompt
追求少量干净 rare 样本
```

长尾微调里，**干净比数量重要**。

------

## 6. 实操上我建议你加一个“准入门槛”

每个 prompt 生成后，统计并人工看 top 样本：

```txt
每个 prompt 抽 top 50
准确率 >= 70%：可以当正样本
准确率 40%~70%：只取 top 高分，低权重
准确率 < 40%：不当正样本
误检有规律：转 hard negative
误检无规律：丢弃
```

比如：

```python
PROMPT_USE_POLICY = {
    "laptop": "positive",
    "monitor": "positive",
    "screen": "hard_negative",
    "keyboard": "positive_if_clean",

    "dustbin": "positive",
    "garbage bin": "positive",
    "bin": "drop",

    "traffic light": "drop_or_separate_test",
    "pole": "hard_negative",
    "window": "building_only_or_drop",
}
```

------

## 最重要的结论

如果近义词映射都很不好：

```txt
不要合并进正样本
不要直接参与 rare 微调
不要为了补数量牺牲 precision
```

改成：

```txt
1. 只保留最干净的原始类：computer / trash can
2. 近义词中干净的少量 top 样本才加入
3. 不干净但误检稳定的，做 hard negative
4. 混乱 prompt 直接丢
5. 最后仍然做 rare-balanced 统一微调
```

一句话：**近义词是用来扩 recall 的，不是必须用；一旦它污染标签，就让它从“正样本工具”变成“负样本工具”。**
