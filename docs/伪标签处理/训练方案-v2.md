# 明天伪标签融合与训练方案记录

## 0. 当前结论

当前主线不要用新的 manifest 全量替换旧标签。

最稳方案是：

```txt
旧主伪标签 / 最全伪标签作为底盘
+
细分动物 clean rare 伪标签补充 animal
+
computer / trash can 等稀有类补充
+
truck / bus 等补充 car
+
去重并集
+
映射到最终 7 类
+
从 clipseg_best.pt 小学习率继续微调
```

原因：

- 旧标签训练出的 CLIPSeg v1 是当前最好基线；
- 之前用更严格 manifest 接 best.pt 训 5 epoch，榜单反而低约 2 分；
- manifest 更严格，可能杀 recall；
- 当前目标是补长尾和补 animal recall，不适合直接替换旧标签。

所以明天策略是：

```txt
旧标签负责保 recall 和主干分数
manifest / A/B/C 分档负责筛干净 rare
clean rare 负责补长尾
```

## 4. 映射规则是什么

映射不是改图，也不是重新跑 SAM3。

映射是：

```txt
mask 不变
image_path 不变
rle 不变
只把 source_prompt 改成最终 train_label
并根据 A/B/C 改 prompt_pool 和 sample_weight
```

例如原始伪标签：

```json
{
  "image_path": "test/data6/xxx.jpg",
  "prompts": {
    "fox": {
      "hit": true,
      "score": 0.84,
      "instances": 1,
      "rle": {}
    }
  }
}
```

映射后：

```json
{
  "image_path": "test/data6/xxx.jpg",
  "train_label": "animal",
  "source_prompt": "fox",
  "grade": "A",
  "prompt_pool": ["animal", "fox"],
  "score": 0.84,
  "instances": 1,
  "rle": {},
  "sample_weight": 1.2
}
```

核心意思：

```txt
fox 检出来的 mask，不作为 fox 类训练
而是作为 animal 类训练样本
```

## 6. 动物 A/B/C 处理规则

### 6.1 A 类

A 类特点：

```txt
种类基本对
框/掩码也对
质量较高
```

处理：

```txt
source_prompt → animal
prompt_pool = ["animal", source_prompt]
sample_weight = 1.0 ~ 1.2
```

推荐：

```python
A_POLICY = {
    "fox": 1.2,
    "tiger": 1.2,
    "wolf": 1.2,
    "lion": 1.2,
    "horse": 1.2,
    "monkey": 1.2,
    "dog": 1.0,

    # 可加但稍轻
    "duck": 0.8,
    "pig": 0.8,
    "rabbit": 0.8,
    "zebra": 0.6,
    "giraffe": 0.8,
}
```

A 类输出样例：

```json
{
  "train_label": "animal",
  "source_prompt": "fox",
  "grade": "A",
  "prompt_pool": ["animal", "fox"],
  "sample_weight": 1.2
}
```

------

### 6.2 B 类

B 类特点：

```txt
细分类经常错
但框/掩码大多在动物上
```

处理：

```txt
source_prompt → animal
prompt_pool = ["animal"]
sample_weight = 0.4 ~ 0.6
```

不要再使用 source_prompt 训练。

原因：

```txt
如果 source_prompt=fox，但实际框到 dog/wolf/其他动物
继续用 fox prompt 会污染文本语义
只用 animal prompt 更稳
```

B 类输出样例：

```json
{
  "train_label": "animal",
  "source_prompt": "fox",
  "grade": "B",
  "prompt_pool": ["animal"],
  "sample_weight": 0.5
}
```

------

### 6.3 C 类

C 类特点：

```txt
细分类基本错
但如果位置确实在动物上，可以作为弱补充
```

处理：

```txt
source_prompt → animal
prompt_pool = ["animal"]
sample_weight = 0.15 ~ 0.25
每图最多保留 1~2 个
```

C 类一定要限量，不要全量强加。

C 类输出样例：

```json
{
  "train_label": "animal",
  "source_prompt": "dog",
  "grade": "C",
  "prompt_pool": ["animal"],
  "sample_weight": 0.2
}
```

## 7. 哪些 B/C 不能改成 animal

如果 B/C 里出现下面情况，直接丢：

```txt
框到非动物
框到人
框到车轮/建筑边缘/树枝/石头/热源噪声
mask 面积特别大，吞掉大片背景
mask 很碎，像噪声块
area_ratio > 0.5
area < 16
```

核心判断：

```txt
细分类错，但框住的是动物 → 可以映射成 animal
框住的不是动物 → 不能映射成 animal
```

## 8. 和原 animal 伪标签怎么合并

映射后，所有细分类都变成：

```txt
train_label = animal
```

需要和原主伪标签里的 animal 做同图同类去重并集。

### 8.1 分组

```python
group_key = (image_path, train_label)
```

例如同一张图里：

```txt
原 animal
fox → animal
wolf → animal
dog → animal
```

全部属于：

```txt
(image_path, "animal")
```

------

### 8.2 重复判断

两个 mask 如果满足任一条件，就认为是同一个目标：

```txt
IoU > 0.6
```

或者：

```txt
intersection / min(area_a, area_b) > 0.8
```

------

### 8.3 重复时保留优先级

优先级：

```txt
原 animal / A 类 > B 类 > C 类
score 高 > score 低
面积正常 > 面积异常
```

可以定义：

```python
GRADE_PRIORITY = {
    "base_animal": 0,
    "A": 1,
    "B": 2,
    "C": 3,
}
```

数字越小优先级越高。

------

### 8.4 取并集是什么意思

不是简单把所有 mask 像素级 OR 后无脑塞进去。

正确流程：

```txt
原 animal 候选
+
fox/wolf/dog/lion 等映射后的 animal 候选
→ 过滤
→ 同图同类去重
→ 保留非重复目标
→ 得到补充后的 animal 集合
```

如果训练格式是 prompt-style，每张图每个 prompt 只能有一个 animal mask，则最后需要：

```txt
final_animal_mask = old_animal_mask OR rare_animal_masks
```

如果训练 manifest 支持一条样本一个 mask，则不用 OR，保留多条实例样本即可。

## 10. 训练时长影响

会变长，但可以控制。

### 情况 1：直接追加样本

如果原训练集约：

```txt
120370 samples
```

追加 rare 后：

```txt
120370 + rare_count
```

epoch 时间会按样本数比例增加。

例如：

```txt
rare_count = 5000
增加约 4%

rare_count = 12000
增加约 10%

rare_count = 20000
增加约 16%+
```

------

### 情况 2：固定每个 epoch 的 step 数

如果训练脚本支持按池子采样：

```txt
主旧标签样本：70%
rare animal：15%
computer/trash can：10%
负样本：5%
```

那么 epoch 时间基本不变，只是样本来源分布改变。

------

### 当前建议

如果训练脚本暂时不支持采样池，就直接控制 rare 数量：

```txt
A：全加
B：低权重加
C：每图最多 1~2 个
rare 总量控制在主训练集 10%~15% 以内
```

如果 rare animal 小于 5000，直接加，训练时长影响很小。

如果 rare animal 5000~15000，可以接受。

如果 rare animal 超过 20000，需要抽样或限量。

------

## 11. 推荐训练配比

如果训练脚本支持采样比例：

```txt
主旧标签：65%~75%
animal clean rare：10%~15%
computer/trash can rare：8%~12%
负样本：5%~10%
```

如果不支持采样比例：

```txt

C 类严格限量
```

## 12. 风险与对应处理

### 风险 1：animal false positive 增加

原因：

```txt
B/C 把非动物区域也映射成 animal
```

处理：

```txt
B/C 只用 animal prompt
C 极低权重
C 每图 top 1~2
明显非动物 drop
```

------

### 风险 2：训练时间变长

原因：

```txt
rare 样本追加过多
```

处理：

```txt
控制 rare 总量
C 类限量
必要时 B/C 抽样
```

------

### 风险 3：覆盖旧基线能力

原因：

```txt
rare 权重过高
学习率过大
训练 epoch 太多
```

处理：

```txt
从 clipseg_best.pt 微调
lr 降到原来的 1/5~1/10
训 2~5 epoch
保留旧主伪标签为主训练底盘
```

------

### 风险 4：manifest 太严格导致 recall 下降

之前已经出现过：

```txt
manifest 接 best.pt 训 5 epoch，榜单低于旧标签基线
```

所以明天不要：

```txt
manifest 全量替换 old pseudo
```

而是：

```txt
old pseudo + clean rare
```

# Animal 细分类伪标签 ABC 映射规则总结

## 1. 总体原则

细分动物 prompt 不作为最终类别训练，最终统一映射到主类：

```txt
rabbit / horse / pig / zebra / duck / lion / tiger / monkey / giraffe / bear / wolf / fox / dog
→ animal
```

映射时：

```txt
mask 不变
image_path 不变
rle 不变
只修改训练标签 train_label = animal
并根据 A/B/C 设置不同 prompt_pool / sample_weight / 是否保留
```

细分类映射后的 animal 需要和 base label 中已有的 `prompts["animal"]` 做去重取并。

其他 base 类：

```txt
person / tree / building / car / computer
```

全部原样保留，不参与修改。

------

## 2. 验证集 val 的 ABC 规则

验证集上 A/B/C 的质量整体比 train 好，因此 val 阶段可以按较完整策略合并，用于验证脚本逻辑和观察补充效果。

### val A 类

A 类质量较高：

```txt
细分类大多正确
框/掩码位置较准
噪声少
```

处理规则：

```txt
source_prompt → animal
prompt_pool = ["animal", source_prompt]
sample_weight = 1.0 ~ 1.2
```

例如：

```json
{
  "source_prompt": "fox",
  "train_label": "animal",
  "grade": "A",
  "prompt_pool": ["animal", "fox"],
  "sample_weight": 1.2
}
```

推荐主要保留：

```txt
fox / tiger / wolf / lion / horse / monkey / dog
```

较弱但 A 档可低权重保留：

```txt
duck / pig / rabbit / zebra / giraffe
```

------

### val B 类

B 类在验证集上表现为：

```txt
细分类经常错
但大部分框/掩码位置仍然在动物上
```

处理规则：

```txt
source_prompt → animal
prompt_pool = ["animal"]
sample_weight = 0.4 ~ 0.6
```

B 类不保留 source_prompt 参与训练，原因是细分类不可靠。
例如 `source_prompt=fox`，实际可能是 dog/wolf/其他动物，如果继续用 `"fox"` prompt 会污染文本语义。

示例：

```json
{
  "source_prompt": "fox",
  "train_label": "animal",
  "grade": "B",
  "prompt_pool": ["animal"],
  "sample_weight": 0.5
}
```

------

### val C 类

C 类在验证集上：

```txt
细分类基本不可靠
但如果框的位置确实在动物上，可以作为极弱 animal 补充
```

处理规则：

```txt
source_prompt → animal
prompt_pool = ["animal"]
sample_weight = 0.15 ~ 0.25
每张图最多保留 1~2 个 C 类 animal
```

示例：

```json
{
  "source_prompt": "dog",
  "train_label": "animal",
  "grade": "C",
  "prompt_pool": ["animal"],
  "sample_weight": 0.2
}
```

C 类只用于验证合并效果，不作为强正样本。

------

## 3. 训练集 train 的 ABC 规则

训练集上观察到：

```txt
C 类不仅类别错，框也不如验证集准，并且有噪声
B 类甚至比 C 更差
A 类也有不少没检出来或质量不稳定的情况
```

因此 train 不能沿用 val 的完整 ABC 策略，需要明显收紧。

------

### train A 类

train 阶段只考虑 A 类，并且 A 类也要再次严格筛选。

保留条件：

```txt
hit = true
rle 不为空
score 达到阈值
mask 面积正常
不是大片背景
不是明显噪声
prompt 在白名单中
```

推荐白名单：

```txt
fox / wolf / lion / tiger / horse / monkey / dog
```

暂时 drop 或谨慎处理：

```txt
duck / pig / rabbit / zebra / giraffe / bear
```

处理规则：

```txt
source_prompt → animal
prompt_pool = ["animal", source_prompt]
sample_weight = 0.8 ~ 0.9
```

相比 val A，train A 权重降低，因为 train A 质量没有 val A 稳。

示例：

```json
{
  "source_prompt": "wolf",
  "train_label": "animal",
  "grade": "A",
  "prompt_pool": ["animal", "wolf"],
  "sample_weight": 0.8
}
```

------

### train B 类

train B 当前不建议使用。

原因：

```txt
train B 质量比预期差
部分框不准
可能引入 animal false positive
细分类不可靠
```

处理规则：

```txt
drop
不映射 animal
不参与训练
```

如果后续必须使用，只能作为极弱候选：

```txt
prompt_pool = ["animal"]
sample_weight = 0.1 ~ 0.2
每张图最多 1 个
```

但当前默认方案是：

```txt
train B = drop
```

------

### train C 类

train C 当前不建议使用。

原因：

```txt
细分类错误多
框位置不稳定
伴随噪声
容易污染 animal 类
```

处理规则：

```txt
drop
不映射 animal
不参与训练
```

当前默认方案是：

```txt
train C = drop
```

------

## 4. val 和 train 的核心区别

| 数据集 | A 类                                      | B 类                                    | C 类                                                |
| ------ | ----------------------------------------- | --------------------------------------- | --------------------------------------------------- |
| val    | 映射 animal，保留 source_prompt，中高权重 | 映射 animal，只用 animal prompt，低权重 | 映射 animal，只用 animal prompt，极低权重，每图限量 |
| train  | 严格筛后映射 animal，低一些权重           | 默认 drop                               | 默认 drop                                           |

原因：

```txt
val ABC 质量较好，可以用于验证合并策略；
train ABC 质量明显变差，不能直接照搬 val 策略，否则会污染训练集。
```

------

## 5. 去重取并规则

细分类映射成 animal 后，需要和 base label 中已有的 `prompts["animal"]` 做去重取并。

### 对比对象

```txt
rare animal candidate
vs
base label 的 prompts["animal"]
```

同时 rare 之间也需要去重：

```txt
rare animal candidate
vs
已经接收的 rare animal candidate
```

------

### 重复判断阈值

如果满足任一条件，认为重复：

```txt
IoU > 0.6
```

或：

```txt
containment > 0.8
```

其中：

```txt
containment = intersection / min(area_a, area_b)
```

------

### 重复时保留谁

```txt
rare 和 base animal 重复：
保留 base animal，丢弃 rare

rare 和已接收 rare 重复：
保留优先级更高/score 更高的 rare
```

优先级建议：

```txt
A > B > C
score 高 > score 低
面积正常 > 面积异常
```

------

### 不重复时怎么合并

不重复的 rare animal 补进 base animal：

```txt
final_animal_mask = base_animal_mask OR kept_rare_animal_masks
```

最后写回：

```txt
prompts["animal"]
```

其他类：

```txt
person / tree / building / car / computer
```

完全不动。

## 6. 最终执行建议

### val 阶段

```txt
输入：
base_val_label_6class.json
pseudo_A.json
pseudo_B.json
pseudo_C.json

处理：
A/B/C 按 val 策略映射 animal
和 base animal 去重取并
输出新的完整 val label

目的：
验证合并逻辑
看 rare animal 是否真的能补 recall
统计 A/B/C 分别保留多少
```

### train 阶段

```txt
输入：
base_train_label_6class.json
pseudo_A.json
pseudo_B.json
pseudo_C.json

处理：
只用严格筛后的 A
B/C 默认 drop
A 映射 animal
和 base animal 去重取并
输出新的完整 train label

目的：
少量补充 animal recall
避免污染主训练集
```

------

## 7. 一句话版本

```txt
val：A/B/C 都可以按不同权重映射成 animal，用来验证合并策略；
train：只用严格筛后的 A 映射成 animal，B/C 暂时丢弃；
所有 rare animal 都必须和 base animal 去重后再取并，其他 5 类原样保留。
```
