# CLIPSeg 模型提交操作指南

## 一、赛题提交要求回顾

| 项目 | 要求 |
|------|------|
| 基础镜像 | `supervisely/sam3:1.0.6` |
| 代码路径 | `/raytron/code/` |
| 模型权重 | `/raytron/code/model/sam3.pt` (FP32) |
| 参数量限制 | ≤ 300M |
| 内存限制 | ≤ 1.5GB |
| 输入 | `/raytron/test/` 下图片 + `test_tasks.json` |
| 输出 | `/raytron/test/predictions.json` |
| 评测指标 | mIoU（初赛）；精度+效率+泛化（决赛） |
| 提交方式 | Docker 镜像 tar.gz → DataFountain 平台 |
| 截止日期 | **2026年6月20日** |

## 二、整体流程

```
训练好的 CLIPSeg 权重 (best.pt)
        │
        ▼
  export_model.py  ──→  model/submit/sam3.pt + configs
        │
        ▼
  docker build -t raytron-submit .
        │
        ▼
  docker save -o raytron-submit.tar raytron-submit  //导出镜像tar
  tar -czf raytron-submit.tar.gz raytron-submit.tar  //压缩成tar.gz
  docker save → raytron-submit.tar.gz
        │
        ▼
  上传 DataFountain 平台
```

## 三、逐步操作

### 步骤 1：确认训练权重

确保 CLIPSeg 训练完成，权重文件存在：

```bash
ls -lh test/train_output/clipseg_v1/best.pt
```

> **当前状态**: ⚠️ 权重尚未训练完成。以下步骤中用到的 `best.pt` 请替换为实际训练产出的路径。

### 步骤 2：导出模型

```bash
cd /c/raytron_project
/d/anconda3/envs/rayton/python.exe src/export_model.py
```

这一步会：
- 从 `test/train_output/clipseg_v1/best.pt` 提取 state_dict
- 从 `model/clipseg-rd64-refined/` 复制 HuggingFace 配置文件
- 输出到 `model/submit/` 目录
- 自动校验参数量是否 ≤ 300M

输出目录结构：
```
model/submit/
├── sam3.pt                 ← CLIPSeg state_dict (~600MB FP32)
├── config.json             ← HuggingFace CLIPSegForImageSegmentation config
├── preprocessor_config.json
├── tokenizer.json
├── tokenizer_config.json
├── vocab.json
├── merges.txt
└── special_tokens_map.json
```

CLIPSeg 参数量约 **150M**（远低于 300M 限制），FP32 权重文件约 600MB（远低于 1.5GB 内存限制）。

### 步骤 3：构建 Docker 镜像

**前置条件**：Docker Desktop 已启动。

```bash
cd /c/raytron_project
docker build -t raytron-submit .
```

构建过程：
1. 基于 `supervisely/sam3:1.0.6`（已含 PyTorch CUDA 版 + pycocotools）
2. 用 `python3 -m pip` 安装 `transformers` + `opencv-python-headless`
3. 复制 `model/submit/` → `/raytron/code/model/`
4. 复制 `inference.py` → `/raytron/code/inference.py`
5. 自动校验所有关键文件和 Python 导入

### 步骤 4：本地验证（可选但推荐）

如果有本地测试数据（test_tasks.json + 图片），可以跑一次完整推理验证：

```bash
docker run --gpus all \
    -v /c/raytron_project/test:/raytron/test \
    raytron-submit \
    python3 /raytron/code/inference.py
```

检查输出的 `predictions.json` 格式是否正确：
```bash
python3 -c "
import json
with open('test/predictions.json') as f:
    data = json.load(f)
print(f'predictions 条数: {len(data[\"predictions\"])}')
print(f'推理耗时: {data[\"timing\"][\"inference_seconds\"]:.1f}s')
print(f'参数量: {data[\"model_info\"][\"total_params\"]:,}')
print(f'第一条: {data[\"predictions\"][0]}')
"
```

### 步骤 5：导出镜像

```bash
docker save raytron-submit | gzip > raytron-submit.tar.gz
```

检查文件大小：
```bash
ls -lh raytron-submit.tar.gz
```

说明：
- 基于 `supervisely/sam3:1.0.6` 的完整镜像导出包可能会比较大，最终 `tar.gz` 不一定只有 `2-3GB`。
- 体积主要受基础镜像大小影响，不是模型参数量超标。
- 比赛硬性限制是**模型参数量 ≤ 300M**，不是 `tar.gz` 文件必须 ≤ 300MB。

### 步骤 5.1：后续重新压缩镜像更快的做法

如果你后面只是小改：
- `inference.py`
- `model/submit/sam3.pt`
- `model/submit/*.json`

那不需要从头清缓存。直接按下面流程做即可：

```bash
cd /c/raytron_project
docker build -t raytron-submit .
docker save -o raytron-submit.tar raytron-submit
tar -czf raytron-submit.tar.gz raytron-submit.tar
```

这样 Docker 会复用已经存在的基础镜像和前面成功构建的层，通常只重做最后几层：
- `COPY model/submit/`
- `COPY inference.py`
- 最后的校验 `RUN`

只有在这些情况才建议全量重建：
- 改了 `FROM supervisely/sam3:1.0.6`
- 改了 `apt-get` 安装内容
- 改了 `pip install` 依赖
- 怀疑旧缓存导致构建内容不一致

这时再用：

```bash
docker build --no-cache -t raytron-submit .
```

额外建议：
- 根目录保留 `.dockerignore`，避免把 `test/`、`.hf_cache/`、`*.tar`、`*.zip` 这些大文件送进构建上下文。
- 如果只是重新训练出新权重，优先只更新 `model/submit/` 后再重建镜像，不要顺手改无关文件。
- `docker save` 本身通常没有进度条，导出大镜像时终端长时间无输出属于正常现象。

### 步骤 6：上传

1. 登录 DataFountain 平台: https://www.datafountain.cn/competitions/1164
2. 进入"作品提交"页面
3. 上传 `raytron-submit.tar.gz`

## 七、常见问题

**Q: 推理速度太慢怎么办？**
A: CLIPSeg 单张图推理约 50-80ms，加预处理约 100ms。如果测试集图多（几千张），总时间在 5-10 分钟内。如需进一步提速，可将 IMG_SIZE 降至 512（牺牲部分精度）。

**Q: 参数量超过 300M 怎么办？**
A: CLIPSeg-rd64-refined 约 150M 参数，远低于限制。export_model.py 会自动校验并警告。

**Q: Docker 构建失败？**
A: 检查 `model/submit/` 目录是否存在（需先运行 export_model.py），确认基础镜像 `supervisely/sam3:1.0.6` 可拉取。

**Q: Docker 构建失败后要不要清缓存？**
A: 通常不用立刻清。Docker 会保留已成功步骤的缓存层，修完 `Dockerfile` 后直接重新执行：

```bash
docker build -t raytron-submit .
```

如果怀疑缓存导致旧内容被复用，可强制全量重建：

```bash
docker build --no-cache -t raytron-submit .
```

如果只是想清理无 tag 的中间层和构建缓存，优先用：

```bash
docker image prune -f
docker builder prune -f
```

如果磁盘占用明显过大、需要彻底重来一次，再用：

```bash
docker builder prune -a -f
```

注意：`-a` 会删除更多可复用缓存，下次构建会明显变慢。
