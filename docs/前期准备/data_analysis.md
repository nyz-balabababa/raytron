## 总结与路线图

**第一阶段只做提示词优化，不动模型 → 用优化后的预测结果作为伪标签 → 第二阶段再用伪标签去训练/微调小模型，最后替换权重**

第一阶段（验证集，只优化prompt）：
    验证集图片 + 初始任务JSON
            ↓
    (EVOL-SAM3自动搜索最优prompt，或手工优化)
            ↓
    SAM3推理 → 高质量伪标签（标准答案）
            ↓
    （同时选择最优的prompt集合，冻结为固定配置）

第二阶段（训练集，可用伪标签训练）：
    优化后的prompt + 5万+红外训练集
            ↓
    SAM3推理 → 生成大规模伪标签
            ↓
    （选择以下技术路线之一）
            ↓
    • SAM3-Adapter（快速验证） → 替代原始SAM3（不满足轻量）
    • 知识蒸馏（满足轻量指标） → 替换原始SAM3（推荐）
            ↓
    最终轻量模型权重（替换 /raytron/code/model/sam3.pt）



| 阶段                        | 任务                                                         | 使用的模型                         | 输入                                        | 输出                                                         |
| :-------------------------- | :----------------------------------------------------------- | :--------------------------------- | :------------------------------------------ | :----------------------------------------------------------- |
| **阶段0：准备验证集**       | 从5万+红外数据中划出一部分作为验证集（不用于训练）           | 无                                 | 无                                          | 验证集图片 + 人工定义的基础prompt列表                        |
| **阶段1：优化prompt**       | 在验证集上尝试不同prompt，找到最佳文本提示                   | **原始SAM3**（冻结）               | 验证集图片 + 候选prompt                     | 最佳prompt集合（例如固定下来：`person`, `car`, `building`等） |

| **阶段5：迭代优化**         | 根据验证集上的表现，调整学生模型的架构、超参数、训练策略等，重复阶段3-4 | 学生模型                           | 同上                                        | 更好的学生模型权重                                           |
| **阶段6：最终提交**         | 将最优学生模型权重替换为 `/raytron/code/model/sam3.pt`，运行官方 `inference.py` 生成最终预测结果 | 学生模型                           | 官方测试集（封闭） + 官方 `test_tasks.json` | `predictions.json` 提交                                      |

------

### 

1. **prompt调优只做一次**：在验证集上用原始SAM3找到最佳prompt后，这个prompt就固定下来，用于后续所有阶段（生成伪标签、训练学生模型、最终预测）。
2. **伪标签来自原始SAM3**：不是来自学生模型。学生模型是学习者，不是伪标签生成者。
3. **学生模型训练的是跨模态对齐能力**：它的权重内部包含文本编码器与视觉编码器的对齐参数，而不是传统分类的权重。
4. **验证阶段对比的是学生模型预测 vs 伪标签**：因为伪标签被视为“参考答案”。你也可以人工抽检一小部分来验证伪标签的质量。
5. **迭代优化的是学生模型**：原始SAM3在整个训练学生模型的过程中保持不变（只用于生成伪标签一次）。学生模型可以反复训练、验证、调参。

### ⚠️ 补充说明

- **伪标签质量决定学生模型上限**：如果原始SAM3在某些类别上预测很差（比如漏掉很多实例），那么学生模型学到的也会差。所以阶段1的prompt优化非常关键。你可以考虑用EVOL-SAM3这种自动搜索最优prompt的工具来提升伪标签质量。
- **学生模型架构必须支持跨模态**：不能随便选一个分类模型。你需要使用类似 `EfficientSAM3`、`SAM3-LiteText` 或 `YOLOv8`（配合文本编码器改造）的架构。
- **训练损失函数**：通常是 mask 分割损失（Dice + Focal 等），不是分类的交叉熵。确保你用的训练框架支持像素级分割任务的损失计算。
- **验证集上的对比**：mIoU 是常用指标。由于验证集本身没有真实标注（只有伪标签），这个 mIoU 只能反映学生模型对伪标签的拟合程度，不代表绝对精度。但你可以在迭代中观察 mIoU 是否持续提升，说明学生模型在学习。最终提交前，最好人工抽查几十张验证图，确认学生模型的预测比原始SAM3更好或相当。

## 接下来的规划：做最好的prompt

分验证集，设计自己的test_tasks.json，用原始sam3预测，得到predictions.json作为基线。

**没有标注（Ground Truth）时，如何判断模型预测的效果好坏？**

你在验证集上运行了 SAM3（原始权重），得到了每个 `ann_id` 的 RLE 预测结果。因为没有任何参考答案，你不能直接算出 mIoU、Dice 等数值指标。但你可以通过以下几种**不需要标注**的方法来定性+半定量评估效果，从而判断你的任务 JSON 设计是否合理、SAM3 在验证集上的表现是否符合预期。

---

## 方法一：可视化抽查（最直观、最推荐）

随机抽取一小部分验证图片（比如 50 张），将预测的 mask 叠加在原图上，肉眼观察分割质量。

### 操作步骤

1. **编写一个可视化脚本**，输入：
   - 验证集图片路径
   - 对应的 `predictions.json`（包含每个 `ann_id` 的 RLE）
   - 任务 JSON（知道每张图有哪些 prompt）

2. **对每张图，对每个 prompt**：
   - 解码 RLE 为二值 mask
   - 在原图上用红色半透明叠加 mask（或绘制轮廓）
   - 保存可视化结果图片，文件名包含 `图片名_prompt.png`

3. **人工查看**，记录以下情况：

| 观察结果                           | 评价 |
| ---------------------------------- | ---- |
| mask 精准覆盖目标，边缘清晰        | 优秀 |
| mask 覆盖了目标但略有溢出/缺失     | 良好 |
| mask 覆盖了错误区域（假阳性）      | 差   |
| 目标存在但 mask 完全为空（假阴性） | 差   |
| 目标不存在且 mask 为空             | 正确 |

4. **统计抽查样本中**：
   - 每个 prompt 的“可用”比例（优秀+良好）
   - 常见的错误模式

### 优点
- 真实反映分割质量
- 可以发现 prompt 设计问题（例如 `animal` 总是乱分割）
- 不需要任何标注

### 缺点
- 只能抽查小样本，不能 100% 覆盖

---

## 方法二：统计预测的“激活率”

对于每个 prompt，计算其在所有验证图片上**输出非空 mask 的比例**（即至少有一个实例命中的比例）。

### 操作思路

1. 遍历 `predictions.json`，按 prompt 分组（注意一个 `ann_id` 对应一个 prompt）。
2. 对于每个 prompt，统计 `rle` 不为空的条数除以该 prompt 的总任务数。
3. 得到“激活率”。

### 解读

| 激活率          | 可能含义                                      |
| --------------- | --------------------------------------------- |
| 过高（> 90%）   | 提示词太泛（如 `object`），模型乱分割，不可信 |
| 过低（< 5%）    | 提示词在数据集中极少出现，或者模型无法识别    |
| 适中（10%~60%） | 提示词对应目标确实存在一定比例，可能合理      |

### 示例
如果 `animal` 的激活率只有 2%，说明你的 1 万张野外图片中可能只有很少的图片真的含有可识别动物，或者 SAM3 没找到。这时你可以考虑去掉该 prompt，或换用更具体的词如 `deer`（如果你知道有鹿）。

---

## 方法三：利用模型自身的置信度分数

`inference.py` 中的 `aggregate_prompt_prediction` 返回了 `score`（该 prompt 所有命中实例中最高置信度）。你可以统计这些置信度的分布。

### 操作

1. 修改 `inference.py` 或在后处理中，记录每个任务对应的 `max_score`。
2. 分析：
   - 高置信度（> 0.8）且 mask 合理的 prompt → 效果好
   - 低置信度（< 0.5）的 mask 往往质量较差

但注意：置信度只是模型内部的估计，不能完全代替人工判断，但可以作为筛选可疑样本的依据。

---

## 方法四：对比不同 prompt 的设计（A/B 测试）

你可以设计多个版本的任务 JSON，例如：
- 版本 A：`["person", "car"]`
- 版本 B：`["human", "vehicle"]`
- 版本 C：`["person", "car", "tree", "building"]`

然后分别运行推理，通过可视化抽查比较哪个版本的 mask 更符合预期。这样可以优化你的 prompt 用词。

---

## 方法五：使用一个外部的高质量模型生成伪标签（作为参考）

如果你能访问一个在其他数据集上表现很好的分割模型（例如在 COCO 上训练的 Mask R-CNN），你可以用它给你的验证集生成伪标签。虽然不完全准确，但可以作为一个粗糙的参考答案，用来计算你的 SAM3 预测与伪标签之间的相似度（如 mIoU）。

### 注意
- 领域不同（COCO 是可见光，你是红外），伪标签可能偏差很大。
- 仅作相对比较，不能作为绝对真理。

---

## 总结：你现在应该怎么做？

| 步骤 | 方法                         | 目的                               |
| ---- | ---------------------------- | ---------------------------------- |
| 1    | **可视化抽查（必做）**       | 直观确认预测是否合理，发现明显错误 |
| 2    | **统计激活率**               | 评估 prompt 是否匹配数据分布       |
| 3    | 根据抽查结果调整 prompt 列表 | 删除无效 prompt，修改措辞          |
| 4    | 重新运行推理，重复步骤 1-3   | 迭代优化任务 JSON                  |

## 可能的问题

Q:任务json中的prompt和官方评分用的prompt不一致可能导致的效果不同

### 自己测试 `person` vs `human` 的差异

快速验证比任何猜测都可靠。从验证集中选几十张含“人”的红外图片，分别用 `person` 和 `human` 跑推理，计算两者的分割结果差异（mIoU，即预测区域与真实区域的重叠度）。通过这种方式可以量化风险。

### 训练时使用多种同义提示词（最推荐）

这是最稳妥的方法：微调/优化阶段，对每张含“人”的训练图片，同时使用 `person`、`human`、`people` 等多个同义词作为提示词。模型会学习到“这些词都指向同一个概念”。官方评测用 `human` 时，你的模型也能稳定识别。代码层面只需要在构造任务 JSON 时为同一条 ann_id 生成多个版本，或在训练时对每个样本做 prompt augmentation。

### 推理阶段使用 Prompt Augmentation 策略

如果训练无法修改，可以在推理阶段做 test-time prompt augmentation：对每个图片，同时用 `person` 和 `human` 推理，然后取两个结果的并集作为最终输出。这样无论官方用哪个词，都能覆盖。缺点是推理时间翻倍。
