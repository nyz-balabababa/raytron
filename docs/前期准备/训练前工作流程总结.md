# 工作流程总结

## 一、数据分析

### 1.1 命名规则分析

使用 `src/filename_analysis.py` 对 `test/` 下 6 个数据文件夹（data1/3/4/5/6/7）的全部图片进行文件名模式分析：

- 将连续数字替换为 `#`，提取数字归一化模式
- 进一步识别语义标签（时间戳 `[TS14]`/`[TS8]`、长序号 `[SEQ]`、中段 ID `[ID]`）
- 统计每种命名规则对应的图片数量
- 输出 `filename_analysis.csv`，分四个 sheet：总体概览、数字归一化模式、语义模式、前缀分布

**关键发现：**

| 文件夹 | 数量 | 主要来源 |
|--------|------|----------|
| data1 | 25,278 | 多源混杂：IRS红外、DJI无人机、NVR监控、热像仪 |
| data3 | 29 | 时间戳+红外帧（视频抽帧） |
| data4 | 24 | DJI无人机帧（含 bmp） |
| data5 | 8,436 | `ir_` 前缀红外图，含分割配对数据 |
| data6 | 8,472 | `bw_` 可见光灰度图，含分割标注帧 |
| data7 | 1,389 | 结构化工控场景：相机位+场景+光照条件命名 |

### 1.2 图像质量分析

使用 `src/image_quality_analysis.py` 对全部图片计算 7 项质量指标：

| 指标 | 计算方法 |
|------|----------|
| 亮度 | 灰度均值 |
| 对比度 | RMS contrast（std/mean） |
| 清晰度 | 拉普拉斯方差（全分辨率） |
| 噪声水平 | 高斯模糊残差标准差 |
| SNR | 20·log₁₀(均值/噪声) |
| 动态范围 | P99 - P01 百分位间距 |
| 分辨率 | 原始宽高 |

按 `文件夹 → 数字归一化模式` 分组统计 mean/median/min/max，计算各指标的变异系数（CV），CV > 0.25 的规则标记为「不一致」。

输出：
- `image_quality_analysis.csv`：339 种命名规则的汇总统计
- `image_quality_outliers.csv`：异质规则的逐张明细

生成分析报告 `docs/质量分析报告.md`，包含各文件夹质量概览、异质问题分析、极端值（最暗/最亮/最低对比度/最低 SNR）及数据预处理建议。

## 二、数据清理

### 2.1 自动清理

使用 `src/delete_bad_images.py`，根据质量分析结果剪切两类图片到 `data/` 目录：

- **极小分辨率**：92×92、384×288 等（热像仪小图、老旧监控）
- **严重低 SNR**：SNR < 10dB 的规则

### 2.2 伪彩色及异常图检测

使用 `src/tools/clean_outliers.py`，对 `test/` 下全部 `data*/` 图片检测四类异常：

| 检测项 | 方法 | 阈值 |
|--------|------|------|
| 彩色图 | HSV 饱和度均值 | > 60 |
| 准星 | 中心区域 Hough 直线 | > 2 条 |
| 截图/边框 | 边缘密度 + 四边边框 | — |
| 文字/UI 叠加 | 顶底 vs 中间高频能量比 | > 2.5 |

输出：
- `test/clean_outliers.csv`：全部图片的检测明细
- `test/clean_outliers_list.txt`：仅彩色图和文字叠加图的路径列表

准星图（1970 张）暂未处理，后续视需要决定是否剔除。

### 2.3 人工筛选

配合 `src/vis_val_browser.py` 图形浏览器，逐张审查异常图，手动剔除不合格样本。

### 2.4 自适应预处理

推理时使用 `src/prompt_test.py` 内置的自适应预处理管线，在 SAM3 推理前对每张图片执行以下步骤：

| 步骤 | 功能 | 自适应策略 |
|------|------|-----------|
| 伪彩色检测 | 将彩色红外图（伪彩色）转为标准灰度 | HSV 饱和度均值 > 60 则 `cv2.COLOR_BGR2GRAY`，否则正常 BGR→GRAY |
| 反色统一 | 确保热目标为亮区 | **基于直方图偏度**：偏度 < -0.3（左偏 → 黑热）自动反色；文件名含 `blackHot` 强制反色作为保底；亮度 > 200 且非 vis 兜底反色 |
| 动态 CLAHE | 局部对比度增强 | std < 35：强增强（clipLimit=2.5, tile=8×8）；35≤std<50：弱增强（clipLimit=1.5, tile=16×16）；std≥50：跳过 |
| 动态降噪 | 去噪保边 | noise > 12：双边滤波（保边）；8<noise≤12：中值滤波（kernel=3）；noise≤8：跳过 |
| 动态锐化 | 边缘增强 | blur < 150：拉普拉斯锐化核；150≤blur<300：USM（sigma=1.0, amount=1.0）；blur≥300：跳过 |

> **2026-05-30 更新**：
> - **已移除尺寸统一（resize）**：改用原始分辨率直接送入 SAM3，防止小目标因缩放丢失。在 RTX 5070 上预估 1.2-1.5 小时内跑完 4,524 张验证集。
> - **反色检测改为直方图偏度法**：`blackHot` 文件名检测作为保底，主体依赖 `E[(x-μ)/σ]³` 计算偏度，左偏（< -0.3）自动判定黑热并反色，不再依赖文件名关键词。解决了 `_pair` 图无法一刀切反色的问题。

质量指标（std / noise_sigma / blur_score）在增强前计算，作为各步骤的自适应触发依据，确保每张图按实际质量差异执行不同强度的处理，而非一刀切。

可通过 `ENABLE_PREPROCESS = True/False` 开关控制是否启用。

## 四、Prompt 实验

### 4.1 实验设置

所有实验使用 `src/prompt_test.py` 执行，配置见该脚本顶部注释。每个实验的流程：

```
读取任务 JSON → 自适应预处理（伪彩色检测/反色统一/尺寸统一/CLAHE/降噪/锐化）
  → SAM3 推理 → 输出 pred JSON + 统计 CSV + mask 可视化
```

### 4.2 实验一：Json1 全验证集

**任务文件**：`test/json/val_tasks1.json`  
**图片**：val_list.txt 全部 4,524 张  
**Prompt**：`["person", "car", "building", "tree", "computer", "animal"]`

**结果**：

| Prompt | 激活率 | avg_score | avg_inst |
|--------|--------|-----------|----------|
| person | 61.9% | 0.83 | 4.2 |
| car | 47.8% | 0.87 | 16.0 |
| building | 47.0% | 0.79 | 5.3 |
| tree | 46.7% | 0.72 | 8.6 |
| animal | 8.7% | 0.79 | 2.4 |
| computer | 0.5% | 0.64 | 3.4 |

### 4.3 实验二：Json2 全验证集

**任务文件**：`test/json/val_tasks2.json`  
**图片**：val_list.txt 全部 4,524 张  
**Prompt**：`["human", "vehicle", "house", "plant", "pc", "wildlife"]`

与 Json1 为同义词/近义词对照实验。

**结果**：

| Prompt | 激活率 | avg_score | avg_inst |
|--------|--------|-----------|----------|
| human | 35.3% | 0.79 | 2.3 |
| vehicle | 51.2% | 0.87 | 16.9 |
| house | 9.0% | 0.68 | 2.1 |
| plant | 23.5% | 0.68 | 6.6 |
| pc | 0.1% | 0.55 | 1.3 |
| wildlife | 1.5% | 0.71 | 2.0 |

**分析**：vehicle 表现与 Json1 的 car 持平；human 显著低于 person（35% vs 62%），说明 SAM3 对 `person` 响应更强；house/wildlife 大幅低于 building/animal，说明精确类别名优于宽泛名。

### 4.4 实验三：Data5+Data7 细分类

**任务文件**：`test/json/data5&7_tasks.json`  
**图片**：val_list_d5d7.txt（1,698 张）  
**Prompt**：`["computer"]`

**结果**：

| Prompt | 激活率 | avg_score | avg_inst |
|--------|--------|-----------|----------|
| computer | 0.9% | 0.63 | 2.6 |

**分析**：data5/7 为工业红外和室内场景，computer 激活率不足 1%，说明验证集中几乎没有可识别的计算机/显示器类目标。建议从 prompt 列表中移除。

**图片**：val_list_d6.txt（900 张）  
**Prompt**：`["lion", "bear", "wild boar", "duck", "swan", "bird", "deer", "fox", "wolf", "zebra", "monkey"]`

**结果**：

| Prompt | 激活率 | avg_score | avg_inst |
|--------|--------|-----------|----------|
| deer | 8.3% | 0.87 | 1.7 |
| fox | 7.2% | 0.79 | 1.7 |
| bird | 5.3% | 0.79 | 4.6 |
| wolf | 2.4% | 0.76 | 1.6 |
| lion | 2.1% | 0.77 | 1.3 |
| duck | 1.6% | 0.80 | 11.5 |
| monkey | 1.4% | 0.75 | 1.4 |

**分析**：data6 为可见光灰度监控图，场景偏户外。deer/fox/bird 激活率相对较高，熊和野猪几乎不激活。整体细粒度动物类激活率偏低（<10%），说明泛化的 `animal` 类在验证集上更实用。

## 五、结论

综合四个实验的激活率、平均置信度和实例数：

- **Json1 表现最优**：person(61.9%)、car(47.8%)、building(47.0%)、tree(46.7%) 四个主要类别覆盖了验证集大量目标场景
- **Json2 同义词/近义词替换效果差**：human(35%) 远低于 person(62%)，house(9%) 远低于 building(47%)，说明 SAM3 对精确类别词的响应远强于宽泛词
- **computer 几乎无激活**：全验证集 0.5%，data5/7 单独测试也仅 0.9%，建议从 prompt 中移除
- **动物细分不如泛化**：data6 的 11 种动物中最好仅 deer(8.3%)，远低于 Json1 中 animal(8.7%) 在 6-prompts 下的表现，说明泛化类名在多类别任务中更有效
- **预处理对推理有益**：伪彩色转灰度消除了彩色噪点干扰，CLAHE 提升低对比度红外图的可用性

**最终选定 Json1 作为最优 prompt 配置，建议移除 computer 类或替换为更实用的类别。**
