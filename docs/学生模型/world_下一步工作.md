# World 实验下一步工作

## 一、当前定位

当前在 `YOLO-World + FastSAM` 上做实验，目标不是把这条模型路线调到最优，而是：

1. 快速验证数据处理链路是否正确
2. 验证新增尾类接入正式训练体系后是否正常参与训练与评估
3. 借助 `world` 训练速度快的特点，排查伪标签、类别映射、标签转换是否存在系统性问题

因此，后续工作的重点应放在“验数”和“验流程”上，而不是继续深挖 `v4` 的负样本采样策略。

## 二、已得到的阶段性结论

### 2.1 `v4` 三类尾类实验的结论

- `computer / trash can / cable connector` 在 `d5&7` 伪标签上是可学的
- 当前最好结果仍然是“纯正样本训练”
- 随机负样本 `1.0x` 是当前“带负样本版本”的最好折中
- 分层负样本 `1.0x` 没有带来提升，不值得继续深挖

### 2.2 当前不应继续做的事

- 不再继续试 `0.8 / 1.2 / 分层变体` 之类的负样本比例微调
- 不先把时间压在 `fire hydrant binary few-shot` 上
- 不把 `world` 当成最终效果最优路线来反复打磨

## 三、接下来工作的主线

## 3.1 第一优先级：做 8 类全训练集验证版

目标不是追求最终性能，而是验证以下问题：

1. `trash can` 和 `cable connector` 并回正式类别体系后，标签转换是否正确
2. 新增类别是否被正确写入 YOLO 标签文件
3. train/val 中新增类别样本数量是否符合预期
4. 训练日志、评估统计、两阶段评估里是否能正常看到新增类别
5. 新增类别是否会在全训练集主线中被完全压死

建议实现方式：

- 基于 `v3` 的 6 类主线扩展为 8 类
- 新增：
  - `trash can`
  - `cable connector`
- 先不要引入复杂负样本采样逻辑
- 先以“跑通 + 验证类别接入正确”为目标

这一步的核心价值是：

- 验证数据处理主线能否承载新增尾类
- 判断 `v4` 中观察到的尾类信号，能否迁移到全训练集主线

## 3.2 第二优先级：人工抽查尾类伪标签质量

重点只看：

- `computer`
- `trash can`
- `cable connector`

每类建议至少抽查三种样本：

1. 高分命中样本
2. 低分命中样本
3. 直觉上疑似漏检的样本

重点确认以下问题：

- prompt 命中了，但 mask 是否合理
- mask 转 bbox 后是否偏离目标
- 一张图多个实例时是否都被保留
- 阈值是否砍掉了大量真阳性
- 是否存在明显的系统性误检模式

这一步的目的不是大规模清洗，而是确认：

- 当前瓶颈主要在数据处理
- 还是在 teacher 伪标签本身

## 3.3 第三优先级：记录 8 类主线中的尾类表现

8 类验证版跑完后，优先关注的不是 overall，而是：

- `computer`
- `trash can`
- `cable connector`

需要重点观察：

1. 新增类在验证集上是否有稳定命中
2. 新增类是否因为主类过强而被压死
3. 新增类的检测与两阶段 mIoU 是否还能保持在可接受范围

如果这三个类在 8 类主线中完全消失，才需要进一步考虑：

- 提升 class-specific oversample
- 单独做类感知采样
- 或改成双模型/双 head 路由

## 四、`fire hydrant` 的处理策略

`fire hydrant` 目前不应阻塞主线。

原因：

- 当前目标是验证数据处理主线是否正确
- `fire hydrant` 属于典型 few-shot 问题
- 它更适合作为独立小实验并行推进，而不是作为当前主线前置条件

建议做法：

- 后续单独补干净样本
- 单独做 binary few-shot
- 等主线验证结束后再决定是否并入正式类别体系

## 五、伪标签质量提升方向

当前更值得投入的伪标签改进方式如下：

### 5.1 按类检查，不做统一处理

优先单独看：

- `computer`
- `trash can`
- `cable connector`

不要把所有类混在一起讨论，否则很难定位真正的问题来源。

### 5.2 继续使用 class-specific threshold

不同类的最优阈值不会一样。后续如需调整，也应按类改，而不是统一升降。

### 5.3 对极少类采用“候选挖掘 + 人工快筛”

对于像 `fire hydrant` 这种极少类，不要继续完全依赖常规伪标签流程。更合理的是：

1. 放宽该类候选阈值
2. 人工快速筛掉明显错误样本
3. 保留少量高质量样本做 few-shot

### 5.4 检查小目标是否在 teacher 或后处理阶段丢失

重点检查：

- 原图推理是否真实保留
- mask 是否过碎
- bbox 提取是否把小目标弄丢
- 多实例时是否只保留了部分结果

## 六、建议执行顺序

建议按以下顺序推进：

1. 新建 `world` 的 8 类全训练集验证版
2. 跑通训练与评估，确认新增两类已正确接入
3. 抽查 `computer / trash can / cable connector` 的伪标签质量
4. 根据 8 类结果，判断尾类是否会在正式主线中被压死
5. 最后再决定是否单独推进 `fire hydrant binary few-shot`

## 七、一句话总结

下一阶段的重点不是继续优化 `v4`，而是利用 `world` 训练快的优势，尽快验证“新增尾类并回全训练集主线后，数据处理和标签链路是否正确”。这一步确认之后，再决定是否继续投入 `fire hydrant` 或更细的伪标签优化。
