# YOLOv11-seg 蒸馏实验记录

## 一、实验定位

本实验是 SAM3 → 学生模型蒸馏路线的 **第一阶段验证**：用 YOLOv11-seg（闭集模型）验证"SAM3 伪标签能否训出可用的轻量分割模型"。

严格来说这**不是完整的知识蒸馏**——学生只继承了 SAM3 对固定类别的分割结果（硬标签），没有继承其开放词汇泛化能力（任意文本→掩码）。真正的蒸馏需要在后续实验中加入文本编码器（CLIP 等）实现开放词汇输入。

| 验证目标 | 方法 |
|----------|------|
| 伪标签可用性 | SAM3 输出的 RLE mask 能否直接作为训练监督信号 |
| 红外域迁移 | COCO 预训练的 YOLO backbone 能否适应红外灰度图 |
| 小目标极限 | 1280 分辨率下 <8px 目标是否能被检测到 |
| 类别不平衡边界 | computer(151张) 在极端过采样下能否学会 |
| 噪声鲁棒性 | 低置信度伪标签过滤 + label smoothing 的效果 |

实验结论将直接决定后续是否切换到 Grounding DINO + EfficientSAM 等开放词汇方案。

## 二、数据概况

### 2.1 数据来源

| 阶段 | 数量 | 说明 |
|------|------|------|
| 原始全量数据 | 50,000+ | 比赛提供，5 个场景红外实拍 |

| SAM3 伪标签 | 39,094 | `pred_train_tasks.json`（10 张路径问题丢失） |

### 2.2 SAM3 伪标签统计（Json1: person/car/building/tree/computer/animal）

| 类别 | 命中图片数 | 总实例数 | 平均实例/图 | 平均 score | p25 score | 特点 |
|------|-----------|---------|------------|-----------|-----------|------|
| car | 25,598 | 440,320 | 17.2 | 0.915 | 0.848 | 主导类，密集（最多 159/图） |
| person | 23,452 | 123,452 | 5.3 | 0.811 | 0.705 | 分布均匀 |
| tree | 22,850 | 217,611 | 9.5 | 0.723 | 0.628 | 实例多但置信度低 |
| building | 21,376 | 123,174 | 5.8 | 0.841 | 0.731 | 大目标为主 |
| animal | 1,858 | 4,902 | 2.6 | 0.812 | 0.653 | 稀有类，置信度分布宽 |
| computer | 151 | 879 | 5.8 | 0.736 | 0.646 | 极端稀有，接近噪声 |

### 2.3 数据特点

- **分辨率**：512×640 占 73.9%，存在 288×384 ~ 1080×1928 多尺度
- **场景**：城市安防、电力巡检、自然荒野、工业园区、室内监控
- **图像类型**：红外灰度图（含部分伪彩色）、少量可见光灰度图
- **密集场景**：1,577 张图单类实例 >50 个
- **小目标**：比赛要求 <8×8 像素目标，占测试集 10%

### 2.4 数据过滤链路

```
原始训练集:                   39,104 张
  SAM3 完全无检出:   -1,311    (3.4%，无伪标签可用)
  低置信度过滤:        -942    (2.4%，所有类别 score 均低于分级阈值)
  ─────────────────────────
  有效图片:          36,841 张
  + 过采样补回:       +4,317   (animal ×3, computer ×10)
  ─────────────────────────
  最终训练集:         41,158 张
```

每步删除都有原因：
- SAM3 无检出（1,311 张）：部分图片场景与 6 个 prompt 不匹配，删不删都没标签可用
- 低置信度过滤（942 张）：SAM3 检出了但很不确定——伪标签当负样本风险太大，直接舍弃
- 过采样补回（+4,317 张）：animal 和 computer 稀有类的补偿，最终数据量比原始还多 5%

## 三、核心设计决策

### 3.1 保留 computer 类的意义

computer 只有 151 张命中图（0.4%）。保留它有双重价值：

1. **极端不平衡的 stress test**：computer 的 170:1 不平衡是对 class weight / 过采样 / 噪声鲁棒性的极限验证。如果 computer 能收敛（mIoU > 0.15），说明不平衡策略有效，animal（15:1）大概率也没问题。反之如果学不会，可以放心删除。
2. **伪标签下限探测**：computer 的 SAM3 平均 score 0.64（全类别最低），用它验证"最差的伪标签能否产生有用的训练信号"。

最终决策标准：训练完后看 computer 的验证指标，mIoU < 0.05 删除，≥ 0.15 保留。

### 3.2 闭集 vs 开放词汇

当前 YOLOv11-seg 只输出 6 个固定类别。赛题要求文本 prompt 输入且测试集包含 zero-shot 类别，因此推理时需要额外加一层 **prompt → class 映射**：

```python
# 用 CLIP/文本相似度 将任意 prompt 映射到最近似类别
# 对于完全不匹配的 prompt → 返回空掩码
```

这不是最终方案，但让当前实验可以验证 YOLO 的分割质量，同时为后续 YOLO-World / Grounding DINO 方案的对比提供 baseline。

## 四、配置参数详解

### 4.1 核心训练参数

| 参数 | 值 | 理由 |
|------|-----|------|
| `MODEL` | yolo11s-seg.pt | s=平衡精度速度（9.4M），n 太小可能欠拟合伪标签 |
| `CLASSES` | person/car/building/tree/animal/computer | 保留 6 类完整验证 |
| `imgsz` | 1280 | 小目标最有效手段。1280 下 8px 目标占图宽 ~0.6%，处于可检测边界。RTX 5070 12GB 可尝试 1440 |
| `batch` | 8 | 与 1280 配合，平衡显存 |
| `STAGE1_EPOCHS` | 150 | 伪标签需要充分训练但不应对噪声过拟合 |
| `STAGE2_EPOCHS` | 50 | 关闭 copy_paste 后精细收敛 |
| `DEVICE` | 0 | 单卡 |

### 4.2 优化器

| 参数 | 值 | 理由 |
|------|-----|------|
| `optimizer` | AdamW | 对伪标签噪声梯度比 SGD 鲁棒，适合 fine-tune |
| `lr0` (阶段一) | 5e-4 | COCO → 红外域差异大，需要比 1e-4 更大的 LR 推动 backbone 适应；再大（>1e-3）在伪标签噪声下会震荡 |
| `lr0` (阶段二) | 1e-5 | 极小 LR，仅做局部精细调整 |
| `lrf` | 0.01 | 最终 LR = lr0 × 0.01 = 5e-6，余弦退火到极小值防止噪声过拟合 |
| `weight_decay` | 0.03 | 配合 5e-4 的较低正则化 |
| `warmup_epochs` | 5 | 5e-4 初始 LR 需要更长的预热期，前 5 轮从 5e-6 线性升到 5e-4 |
| `cos_lr` | True | 余弦退火比 step decay 对伪标签更平滑 |

### 4.3 正则化

| 参数 | 值 | 理由 |
|------|-----|------|
| `label_smoothing` | 0.1 | **关键**。伪标签不是真值（SAM3 有误检/漏检），label smoothing 防止模型对错误伪标签产生 100% 置信度 |
| `dropout` | 0.1 | 分割头加 dropout，额外正则化。不做太强（0.2+），否则小目标特征被洗掉 |

### 4.4 loss 权重

| 参数 | 值 | 理由 |
|------|-----|------|
| `cls` (分类 loss) | 0.3 | 从默认 0.5 降低。SAM3 的类别判定本身不够可靠，让分割 loss 主导训练 |
| `box` (框 loss) | 7.5 | 保持默认。实例位置的监督信号相对可靠 |

### 4.5 数据增强

| 参数 | 值 | 理由 |
|------|-----|------|
| `mosaic` | 0.0 | **强烈关闭**。mosaic 把 4 张图拼成 1 张，8px 目标变成 2-3px，直接不可检测。红外小目标场景的硬性限制 |
| `copy_paste` (阶段一) | 0.3 | 开启但不过激。0.5 在密集场景（car 最多 159 实例/图）中会过度拥挤；0.3 平衡实例增加和场景真实性 |
| `copy_paste` (阶段二) | 0.0 | 关闭，让模型在原始数据分布上精细收敛 |
| `scale` | 0.3 | 从默认 0.5 降低。对 <8px 目标，0.5 的随机裁剪缩放可能直接切掉目标；0.3 保留多尺度鲁棒性且不过度激进 |
| `degrees` | 0.0 | 关闭旋转。红外小目标旋转后纹理特征消失，旋转增强只会引入噪声 |
| `flipud` | 0.0 | 红外场景有重力方向（车辆/行人不会倒立） |
| `fliplr` | 0.5 | 水平翻转合理（道路左右对称） |
| `hsv_h/s` | 0.0 | 灰度红外无色相/饱和度 |
| `hsv_v` | 0.15 | 亮度微调模拟不同热成像增益值 |

## 五、小目标专项策略

赛题要求 <8×8 像素目标占测试集 10%，以下是与训练参数配套的策略：

### 5.1 高分辨率输入（已实施）
`imgsz=1280` 是应对小目标最直接有效的手段。在 1280×1280 下，8px 目标占 ~0.6% 图幅，属于 YOLO 可检测的下限。若显存允许升至 1440 或 1536 效果更好。

### 5.2 增强策略保护小目标（已实施）
- 关 mosaic（拼图缩小目标）
- 降 scale（避免剧烈缩放丢失目标）
- 关 degrees（旋转破坏小目标特征）

### 5.3 待实施：P2 检测头
YOLOv11 默认有 P3/P4/P5 三层检测头（stride 8/16/32）。对于 <8px 目标，P3（stride=8）的特征图上目标仅 1px，几乎不可检测。增加 P2 层（stride=4）使 8px 目标在特征图上占 2px，显著提升召回。

代价：参数量增加约 15%，推理速度略降。需修改模型结构或使用 `yolo11s-seg-p2.pt` 变体（如果 Ultralytics 提供）。

### 5.4 待实施：NWD Loss
对小目标（<16px），传统 IoU/CIoU loss 在微小位置偏移下剧烈变化，训练不稳定。Normalized Wasserstein Distance (NWD) loss 对小目标梯度更平滑。Ultralytics 原生不支持，需自定义 loss 实现。

## 六、类别不平衡处理

### 6.1 问题规模

```
car      : 25,598 (65.5%) ████████████████████████████████
person   : 23,452 (60.0%) ██████████████████████████████
tree     : 22,850 (58.5%) █████████████████████████████
building : 21,376 (54.7%) ███████████████████████████
animal   :  1,858 ( 4.8%) ███                         ← 15:1 vs car
computer :    151 ( 0.4%) ▎                            ← 170:1 vs car
```

### 6.2 过采样策略（已实施）

在 YOLO 数据集构建阶段，直接复制图片文件实现过采样：

| 类别 | 倍数 | 原始张数 | 过采样后有效张数 |
|------|------|---------|----------------|
| animal | 3× | 1,858 | ~5,574 |
| computer | 10× | 151 | ~1,510 |

实现方式：`convert_dataset()` 阶段 B —— 先写入所有唯一图片，再对包含稀有类的图片额外复制（multiplier - 1）次。利用文件级复制，完全兼容 Ultralytics 训练管线，不需自定义 Dataset 类。

### 6.3 分级置信度过滤（已实施）

不同类别的 SAM3 score 分布差异大，一刀切阈值不合理：

| 类别 | 阈值 | 理由 |
|------|------|------|
| person | 0.70 | p25=0.705，丢弃 ~24% |
| car | 0.70 | p25=0.848，仅丢弃 ~8% |
| building | 0.70 | p25=0.731，丢弃 ~21% |
| tree | 0.60 | p25=0.628，降到 0.6 多保留 ~5,000 张 |
| animal | 0.60 | p25=0.653，稀有类降低门槛 |
| computer | 0.55 | 仅 151 张，能用的都保留（最终保留 137 张） |

实现：`CONF_FILTER` 可为 `float`（统一阈值）或 `dict`（分级阈值）。`make_label_content()` 内部根据类别取对应阈值。

## 七、训练脚本改动说明

### 7.1 文件结构（v3 最终）

```
src/train/
├── config_common.py     ← 所有模型基线共享（数据、过滤、增强、训练骨架）
├── config.py            ← YOLO 专用，from config_common import *
└── yolov11_seg.py       ← 训练主脚本
```

**设计原则**：换模型做对比实验时，只需写新的 `config_<model>.py`，`from config_common import *` 继承公共参数，追加模型专用参数。数据侧的过滤/过采样/增强策略天然一致，对比结果才有说服力。

**config_common.py 管辖**（跨模型锁死）：

| 分组 | 变量 | 说明 |
|------|------|------|
| 数据 | `CLASSES`, `PRED_JSON`, `IMAGE_ROOT` | 同一份伪标签 |
| 过滤 | `CONF_FILTER` | 分级阈值，所有模型统一 |
| 采样 | `RARE_OVERSAMPLE` | animal 3x, computer 10x |
| 训练骨架 | `IMG_SIZE`, `BATCH`, `STAGE1/2_EPOCHS`, `STAGE1/2_LR0` | 同分辨率和训练预算 |
| 优化器 | `OPTIMIZER`, `LRF`, `WEIGHT_DECAY`, `WARMUP_*`, `COS_LR` | 默认 AdamW |
| 正则化 | `LABEL_SMOOTHING`, `DROPOUT` | 伪标签场景通用 |
| 红外增强 | `FLIPUD`, `FLIPLR`, `HSV_H/S/V` | 域相关增强统一 |
| 输出 | `PROJECT`, `EXIST_OK` | train_output/ |

**config.py 管辖**（YOLO 专用）：

| 分组 | 变量 | 说明 |
|------|------|------|
| 模型 | `MODEL`, `TASK`, `YOLO_DIR` | yolo11s-seg |
| 映射 | `STAGE1_IMG_SIZE` = `IMG_SIZE` | 从公共常量映射 |
| loss | `CLS_LOSS_GAIN`, `BOX_LOSS_GAIN` | YOLO 专用 loss 权重 |
| 增强 | `MOSAIC`, `COPY_PASTE`, `SCALE`, `DEGREES`, `CLOSE_MOSAIC` | YOLO 专用增强 |
| 输出 | `RUN_NAME` | yolo11s_seg_v3 |

### 7.2 当前 vs 未来蒸馏训练输入

```
现在 YOLO（闭集）:
  输入: 图像
  输出: [person_mask, car_mask, ...]   ← 6 个固定类别通道
  
  文本 "car" 不进入模型，分类头第 1 通道 = car（硬编码）

未来 CLIPSeg（开放词汇）:
  输入: 图像 + "car"       → mask
  输入: 图像 + "vehicle"   → 同一份 mask（同义 prompt 共享标签）
  输入: 图像 + "汽车"      → 同一份 mask
  
  文本进入 CLIP encoder，模型学习 text_embedding → mask 的对齐
  prompt 扩充不增加 SAM3 推理，只是训练样本数膨胀
```

### 7.3 相比初版的改动

| 组件 | 初版 | v3 | 改动理由 |
|------|------|-----|---------|
| 数据转换 | 全量转换 | + 置信度过滤 + 空标签跳过 + 过采样 | 质量 > 数量 |
| 训练策略 | 单阶段 300 epoch | 两阶段 150+50 | 防止噪声过拟合 |
| 类别处理 | 统一权重 | 过采样 + 分级阈值 | 缓解 170:1 不平衡 |
| 正则化 | 无 | label_smoothing + dropout | 伪标签噪声 |
| LR 策略 | lr0=1e-4 无 warmup | lr0=5e-4 warmup=5 cos_lr | 红外域迁移需更大 LR |

### 7.4 convert_dataset() 流程

```
1. 读取 pred_train_tasks.json
2. 按 image_path 分组
3. 对每张图：
   a. make_label_content() → 分级阈值过滤 → YOLO polygon 行
   b. 若 label_lines 为空 → 跳过（不复制图片）
   c. 若包含 animal/computer → 记录 multiplier（3 或 10）
4. 阶段 B：对稀有类图片额外复制 multiplier-1 次
5. 生成 dataset.yaml
```

### 7.5 分阶段训练流程

```
阶段一 (train_stage):
  - 150 epochs
  - lr0=5e-4, warmup 5 epochs
  - copy_paste=0.3, 全部增强
  - 输出: best.pt

阶段二 (train_stage):
  - 50 epochs  
  - lr0=1e-5（极小 LR）
  - copy_paste=0.0（关闭）
  - 从阶段一 best.pt 加载
  - 输出: 最终 best.pt
```

输出路径：
```
test/train_output/yolo11s_seg_v3_stage1/weights/best.pt
test/train_output/yolo11s_seg_v3_stage2/weights/best.pt  ← 最终模型
```

## 八、本次实验的意义

### 8.1 这个实验在测什么

YOLOv11-seg 是一个闭集模型——训练时只输入图像，文本不参与。它不能替代 SAM3，也不是真正的蒸馏。那它为什么值得跑？

**它验证的不是"模型能不能听懂文本"，而是"轻量 backbone 能不能从 SAM3 伪标签里学会红外分割"**——这是蒸馏路线的地基。地基不稳，后面搭什么都会塌。

### 8.2 结论能回答的 5 个问题

| 问题 | 如果成功（mIoU 可用） | 如果失败（mIoU 很低） |
|------|----------------------|----------------------|
| **伪标签质量够吗？** | SAM3 的 RLE mask 可以直接当监督信号，后续蒸馏信心充足 | 伪标签有系统性问题（RLE 解出来的 mask 有错、polygon 逼近丢失太多），需要排查 |
| **红外域迁移可行吗？** | COCO 预训练 backbone + 红外灰度图可以工作，无需专用预训练 | 需要红外域预训练 backbone（如在大规模红外数据上自监督预训练），否则蒸馏也学不动 |
| **小目标能检测到吗？** | 1280 分辨率 + 增强策略对 <8px 目标有效 | 需要加 P2 层或换检测头结构，小目标是系统瓶颈 |
| **类别不平衡能缓解吗？** | 过采样 + 分级阈值策略有效，后续蒸馏可以复用 | 需要更强的长尾策略（focal loss、class-balanced sampling）或直接删稀有类 |
| **伪标签噪声扛得住吗？** | label_smoothing + dropout + 两阶段训练有效，后续蒸馏复用 | 需要更强的噪声鲁棒训练策略（co-teaching、confidence-weighted loss） |

### 8.3 对后续蒸馏实验的具体影响

**如果 YOLO 训练成功**（验证集 mIoU 在一段时间内持续收敛，visualization 合理）：
- 数据管线（过滤/过采样/分级阈值）确认可用 → 直接复制到蒸馏数据加载器
- 增强策略（关 mosaic、降 scale、域相关 flip/hsv）确认有效 → 蒸馏时复用
- 训练策略（两阶段、warmup、label_smoothing）确认可行 → 蒸馏时参考
- 有可用的 **baseline mIoU** —— 蒸馏模型的 mIoU 必须显著高于这个值，否则蒸馏没有意义
- 伪标签质量风险排除 → 可以把精力和时间集中在模型架构上

**如果 YOLO 训练失败**（loss 不收敛或 visualization 一片混乱）：
- 问题出在更底层（伪标签格式、红外图像质量、小目标极限），换什么模型都会遇到
- 避免了在蒸馏模型上踩同一个坑浪费数天时间
- 可以聚焦排查数据侧的问题再重训

### 8.4 它不是什么

- **不是蒸馏模型**：文本 prompt 从不进入模型，5 个类别的 class_id 是硬编码的，不具备开放词汇能力
- **不能直接提交**：推理时用 `prompt → class_id` 的硬映射，遇到"发热异常的绝缘子"这种训练时没见过的文本就束手无策
- **不是最终方案**：它是蒸馏路线的 **前置验证实验**，目标是降低后续实验的风险

### 8.5 位置

```
蒸馏实验路线:

  YOLOv11-seg 实验 ← 你现在在这里
  ├─ 验证: 伪标签能不能训轻量模型
  ├─ 产出: baseline mIoU + 数据管线 + 增强策略
  │
  ├─ 成功 → CLIPSeg / Grounding DINO + EfficentSAM 蒸馏
  │         └─ 复用全部数据管线，聚焦模型架构
  │
  └─ 失败 → 排查数据侧问题 → 修复 → 重训 YOLO → 再蒸馏
```
