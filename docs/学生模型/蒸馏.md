# 知识蒸馏在 SAM3 → 轻量模型训练中的总结

## 一、什么是知识蒸馏？

知识蒸馏（Knowledge Distillation）是一种特殊的训练方式，核心思想是**让学生模型模仿教师模型的行为**，而不仅仅是学习最终的硬标签。

| 对比项   | 常规训练 / 伪标签训练       | 知识蒸馏                                 |
| -------- | --------------------------- | ---------------------------------------- |
| 监督信号 | 硬标签（二值掩码 0/1）      | 软标签（教师输出的概率分布或特征）       |
| 信息量   | 只有最终判断（是/否）       | 包含不确定性、边界区域的细致评估         |
| 损失函数 | 任务损失（BCE, Dice, etc.） | 任务损失 + 蒸馏损失（KL散度, MSE, etc.） |
| 学生学到 | 正确答案                    | 教师的“思考过程”                         |

## 二、你当前的做法：伪标签训练（不是蒸馏）

**流程**：
1. SAM3 对训练集（图片 + prompt）推理 → 得到二值掩码（硬标签）。
2. 学生模型（如 CLIPSeg）在这些硬标签上做有监督训练，损失 = BCE + Dice。

**本质**：伪标签训练（Pseudo-labeling） / 自训练（Self-training），不属于知识蒸馏。

**优点**：简单直接，符合比赛基本要求，学生模型（CLIPSeg 150M）已满足 ≤300M 限制。

## 三、真正的蒸馏需要什么？

### 3.1 教师模型的软输出

- **硬标签**（你现在的伪标签）：二值矩阵，每个像素 0 或 1。
- **软标签**：教师模型输出的**未二值化的 logits**（或 sigmoid 后的概率图），例如 0.95、0.6、0.1，包含了模型对每个像素的“确信度”和边界模糊区域的信息。

### 3.2 蒸馏损失

在学生原有损失（BCE + Dice）基础上，加入蒸馏损失，让学生模仿教师的软输出：

| 蒸馏类型    | 实现方式                     | 公式示例                                    |
| ----------- | ---------------------------- | ------------------------------------------- |
| Logits 对齐 | 学生对数几率 vs 教师对数几率 | `MSE(logits_student, logits_teacher)`       |
| 概率对齐    | 学生概率 vs 教师概率         | `KL(σ(logits_student) ∥ σ(logits_teacher))` |
| 特征对齐    | 中间特征图                   | `MSE(feat_student, feat_teacher)`           |

### 3.3 总损失

```
Loss_total = λ_task * Loss_task + λ_distill * Loss_distill
```

- `λ_distill` 通常从 0.1 开始尝试。
- 蒸馏阶段一般只做**微调**（5~10 个 epoch，学习率降低 10 倍），不从头训练。

## 四、如何获取 SAM3 的软输出？

### 4.1 格式

- SAM3 的软输出通常是**未经 sigmoid 的 logits**（大小与输入图像相同，取值范围 ~ -10 到 +10）。
- 通过 sigmoid 后得到概率图（0~1）。

### 4.2 获取方式

需要修改 SAM3 的推理代码，直接获取 `logits` 而非二值化后的掩码。常见 API：

```python
outputs = model(pixel_values=img, input_ids=input_ids, ...)
logits = outputs.logits   # 形状 (1, 1, H, W)
```

### 4.3 挑战

- **存储开销大**：每张 1024×1024 的概率图约 4 MB（float32）。训练集 39k 张 → 约 156 GB。
- **解决方案**：
  - 实时生成：训练学生模型时同时前向 SAM3（不保存软标签），显存加倍。
  - 只保存部分困难样本的软标签用于微调。
  - 使用 `float16` 存储，减半大小。

## 五、推荐的两阶段策略

你提出的思路完全正确：**先用伪标签（硬标签）训练基线，再用蒸馏（软标签）微调**。

| 阶段 | 目标                        | 数据                 | 损失                  |
| ---- | --------------------------- | -------------------- | --------------------- |
| 1    | 快速验证学生架构 + 获得基线 | 硬标签（已具备）     | BCE + Dice            |
| 2    | 进一步提升性能              | 软标签（需额外获取） | BCE + Dice + 蒸馏损失 |

**实践步骤**：
1. 用现有伪标签训练 CLIPSeg（或对比 YOLO-World），得到最佳学生模型。
2. 对训练集（或子集）用 SAM3 推理生成软标签（logits 或概率图）。
3. 修改学生训练脚本，加入蒸馏损失，用更小的学习率微调 5~10 个 epoch。
4. 验证集评估，若 mIoU 有提升（通常 2~5 个点），则作为最终提交模型。

## 六、与比赛的关系

- **比赛不强制蒸馏**，只要模型参数量 ≤300M、内存 ≤1.5G 即可。
- 你用伪标签训练的 CLIPSeg（150M）完全符合要求，可以直接提交。
- 蒸馏是可选的**进阶优化**，如果时间充裕且希望冲击更高分数，再尝试。

## 七、结论

- 你当前的伪标签训练是正确、高效的比赛路线，**不是真正的蒸馏**，但可以产出合格的轻量模型。
- 真正的蒸馏需要 SAM3 的软输出（logits/概率）和额外的蒸馏损失，实施复杂度更高。
- 建议：**先跑完伪标签基线（CLIPSeg 25 轮），拿到 mIoU 数据**。如果效果满意，直接作为主力模型；如果不理想且有精力，再实现蒸馏微调。
